## 阶段

### P0 — 立仓（进行中）

- ~~目录骨架与文档~~ → 本次提交：`libs/`、`stages/`、`third_party/`、`tools/`、
  `deploy/`、`scripts/`、`docs/`、`agent-doc/`，每个目录的 `README.md` 说明用途。
- 仓根 `Makefile`、各包的 `pyproject.toml`、CI —— 未建。
- 契约门禁（`tools/contract_review`）—— 未建。

### P1 — 评测闭环先通

**完成判据**：用官方评测脚本对一个平凡策略（零动作或纯运动学回放）在 Tier 1 上跑出
一份提交物，本地复算的分数与脚本输出一致，且成功提交一次、在榜单上看到分数。

先通评测再做训练，理由是后面每一步的改进都要靠这个分数判断；评测链不通时训练得再好
也无从验证。

### P2 — Tier 1 策略

**完成判据**：Tier 1 上训出的策略在本地复算分数上显著超过 P1 的平凡基线，并提交。

### P3 — Tier 2 轨迹恢复

**完成判据**：`recovery` 输出的轨迹在 Tier 2 上带来的分数提升可测，且档位隔离有测试守。

### P4 — Tier 3 重建

**完成判据**：从 exo 视频出发的重建（自研或改进 CARI4D）走通同一条下游并提交。

P3 与 P4 依赖 P1 的评测闭环与 P2 的下游管线，两者之间可并行。

## 待写的 ADR

以下决定在动手前需要落成 ADR，编号按落地顺序分配：

- 官方 toolkit 的接入方式：git submodule、固定 commit 的本地 checkout，还是按需拷贝
  （`third_party/`）。
- Isaac 侧的运行环境：Isaac Lab / Isaac Sim 版本、容器基础镜像、GPU 机器从哪来。
- 环节之间的交接格式：`recovery` 与 `retarget` 之间传什么（沿用 LeRobot v2.1 还是
  官方 parquet 分区）、坐标系与帧号的约定。
- 本地评测与官方评测的关系：复算哪些指标、偏差多大算对账失败。
- 实验记录的形态：`runs/` 下的目录约定、哪些元数据必须随每次运行落盘。
