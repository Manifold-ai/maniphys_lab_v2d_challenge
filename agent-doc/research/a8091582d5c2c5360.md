## A. Contact-aware refinement of noisy hand-object poses

### A1. The two that actually matter

**GeneOH Diffusion** (ICLR 2024, Xueyi Liu & Li Yi) — **this is the TOCH successor and my #1 pick.**
- arXiv: https://arxiv.org/abs/2402.14810 · Code: https://github.com/Meowuu7/GeneOH-Diffusion · Project: https://meowuu7.github.io/GeneOH-Diffusion/ · HF demo: https://huggingface.co/spaces/xymeow7/gene-hoi-denoising (was erroring when I checked)
- **License: MIT. Pretrained checkpoints released** (`ckpts/model.pt` = motion diffusion, `ckpts/model_spatial.pt` = spatial diffusion, Google Drive).
- Representation "GeneOH" has 3 parts: (i) canonicalized hand trajectory `J̄ₖ = (Jₖ − tₖ)Rₖᵀ` (21 keypoints, object frame); (ii) **spatial relations** — hand-object offsets, object normals, relative positions at "generalized contact points" (object surface points within 5 mm of the hand); (iii) **temporal relations** — relative velocity decomposed into tangential/normal components with exponential distance weighting `e^(−k·d)·k_β·‖v⊥‖`.
- Denoising = three stages: **MotionDiff → SpatialDiff → TemporalDiff**, using "diffusion via denoising": push the noisy input forward into a *whitened canonical noise space*, then run a canonical denoiser. That's what gives cross-domain generalization (train on GRAB, test on HOI4D zero-shot).
- Benchmarks + noise: GRAB (Gaussian σ=0.01/0.1/0.5 on MANO params), GRAB-Beta (B(8,2)), HOI4D (real sensing/estimation error), ARCTIC (bimanual + dynamic contacts), TACO.
- **vs TOCH on HOI4D (zero-shot, trained only on GRAB):** intersection volume 4.09 → **1.99 cm³**; penetration depth 4.46 → **2.15 mm**; hand-object motion consistency 35.93 → **9.81 mm²**. GRAB MPJPE: TOCH 12.38 → **9.28 mm**.
- **Stated limitation, and it's the one that bites you:** *"The main limitation lies in the assumption of accurate object pose trajectories."* In V2D the object pose is given but may itself be corrupted — so run object-pose smoothing first, or accept residual error.
- Practical friction: Python 3.8.13 / torch 2.2.0+cu121; needs `manopth`; ~42 GB VRAM for *training* (inference far less); repo TODOs still list ARCTIC eval and more TACO examples; custom-object path is under-documented. Budget ~1 week to wire in.

**TOCH** (ECCV 2022, Zhou et al., MPI) — **historically important, but I'd skip it.**
- arXiv: https://arxiv.org/abs/2205.07982 · Code: https://github.com/kzhou23/toch · Project: https://virtualhumans.mpi-inf.mpg.de/toch/
- TOCH field = per object surface point `(cᵢ, dᵢ, yᵢ)`: binary correspondence flag, signed distance to the corresponding hand point, and the corresponding point's coordinates on the canonical MANO template. Correspondences found by ray-casting along object surface normals (negative direction if the point is inside the hand). Architecture: PointNet-like per-frame encoder/decoder + **bidirectional GRU** temporal denoising autoencoder; loss = L2 recon + weighted distance + BCE on the correspondence flag.
- Training corruption (synthetic, on GRAB): GRAB-T translation noise σ 0.01–0.02 m; GRAB-R rotation noise σ 0.3–0.5 rad; GRAB-B combined (0.01 m + 0.3 rad). Results GRAB-B: MPJPE 17.3 → 10.3 mm, IV 2.20 → 1.78 cm³, contact-IoU 1.76% → **26.6%**. HO-3D: 9.32 mm, beating ContactOpt / RefineNet / Hasson et al.
- **Verdict: half-vaporware.** Code exists, but **no pretrained weights** — two open issues asking for them (#2 from Nov 2022, #4 from Sep 2025), no maintainer reply. **No LICENSE file** in the repo. Custom-dataset prep and inference are literally marked `TODO`. You'd be retraining on GRAB from scratch. Runtime is also bad: ~2 s/frame just to compute the field (2000 points, 48k-vert object), hand fitting ~1 fps.

### A5. 2025–2026 contact refinement / physical-plausibility correction

- **CHOIR** (arXiv:2605.20992, 2026, Xu/Liu/Wang/Fu/Mitra) — https://arxiv.org/html/2605.20992. Closest published thing to "contact-aware refinement done properly." Stage 3 is a test-time joint optimization with a **soft contact cache** (periodically rebuilt top-K MANO-vertex ↔ object-face barycentric correspondences, gated by proximity + normal compatibility + temporal persistence) and losses `L = λ_con·L_con + λ_pen·L_pen + λ_sil·L_sil + λ_anc·L_anc + λ_temp·L_temp`, with a **5 mm dead zone** on penetration. Penetration ratio 4.58% vs HOLD 17.72%, MagicHOI 14.11%. **~30 min per 200-frame video on a 4090** (Stage 3 alone is only ~2 min). **Code availability unconfirmed.** The loss recipe is worth reimplementing even if code never lands.

## B. Force-closure / grasp-stability-based repair

### B1. The core kernel you should steal: DexGraspNet's energy

**DexGraspNet** (ICRA 2023) — https://arxiv.org/abs/2210.02697 · https://github.com/PKU-EPIC/DexGraspNet · **CC BY-NC 4.0**. Source of the energies: `grasp_generation/utils/energy.py`.

```
E_fc    = ‖ contact_normal @ G ‖²      # G = [I | skew-transform of contact points]; differentiable force closure (Liu et al.)
E_dis   = Σ |signed_distance|          # hand contact points → object surface (kills floating hands)
E_pen   = Σ max(0, −sdf)               # hand points inside object (kills penetration)
E_spen  = hand_model.self_penetration()
E_joints= Σ relu(q − q_hi) + relu(q_lo − q)
E = E_fc + 100·E_dis + 100·E_pen + 10·E_spen + 1·E_joints
```

**This is your repair objective.** The papers all use it for synthesis-from-random-init; nobody markets it as a projector, but initializing the optimizer *at your retargeted noisy Dex3 pose* and running a few hundred Adam steps with a trust region on the wrist is exactly "project a noisy grasp onto the nearest force-closure grasp." ~200 lines with `pytorch_kinematics` + a Dex3 URDF. Validated against Isaac Gym in the original paper. ShadowHand on main; Allegro/MANO on branches.

Upstream: **Differentiable Force Closure Estimator** (Liu et al., RA-L 2021) — https://github.com/tengyu-liu/diverse-and-stable-grasp, **MIT**, deps just numpy/trimesh/plotly/torch/manopth. MANO-only (`mano`, `mano_fingertip`), forward synthesis only (`python synthesis.py`), no projection API — but tiny and readable.

### B3. Simulation grasp validation (shake tests)

Standard criteria across DexGraspNet / DexGraspNet2 / D(R,O) Grasp / DexFuncGrasp:
- Hand-object mesh penetration **< 2–3 mm**, self-penetration **< 3 mm**, before anything else.
- Apply gravity along all **6 axis-aligned directions**, 1 s each (or 60–100 steps at 60 Hz); success if the object displaces **< 2 cm** / the hand is still in contact.
- Isaac Gym/Lab refs: DexGraspNet `validate.py`; https://github.com/hjlllll/DexFuncGrasp; https://github.com/IRVLUTD/GenDexGrasp_Test. Caution on https://github.com/abyyworld/isaac-grasp-scaling — MIT, but its README admits the **Isaac Lab backend was never run against the real simulator**.
- MuJoCo ref: DexGraspBench (above).
- **Isaac Lab `ContactSensor`** — https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/sensors/contact_sensor.html. Gives `net_forces_w` and `force_matrix_w` (per-filtered-object breakdown via `filter_prim_paths_expr`), plus `history_length` and air-time. **Gotcha: if `prim_path` regex matches multiple bodies, `force_matrix_w` returns `None`** — so instantiate one sensor per Dex3 fingertip/phalanx if you want per-object contact.

**The three transferable techniques from this section:**

1. **DexMan's contact-prior attraction reward.** Establishes correspondence between designated robot hand keypoints and the object vertices the *human* contacted, then rewards (a) exponential decay in keypoint↔vertex distance, (b) dot-product alignment of the approach vector with the object surface normal, (c) an object-lifted bonus. It explicitly "shifts focus away from imitating ineffective hand trajectories towards fulfilling object-centric contact goals." **Ablation: removing contact rewards drops success 27.4% → 7.2%.** That is the strongest published evidence that contact repair matters for exactly your scoring function. Also: DexMan's **stable-configuration sampling** — perturb the pose randomly (±45° rotations), simulate each, keep the stable config closest to the original → 98% stability. That's a physics-based repair you can run offline in an afternoon.

2. **DexMachina's pipeline.** Virtual object controllers = spring-damper PD on 6 virtual base joints + 1 articulation joint, gains `(kp, kv)` **exponentially decayed based on a history of past rewards** (Algorithm 1), stopping at 0.01. Reward `r = λ_task·r_task + λ_imi·r_imi + λ_bc·r_bc + λ_con·r_con`, where `r_con` is a **masked L2 between policy and demonstration contact positions on object mesh vertices**. And critically for you: *"object-aware post-processing that fixes objects and replays retargeted joints in simulation to resolve penetrations before extracting feasible reference positions."* That is a contact repair step hiding in a retargeting paper.

3. **ManipTrans's noise-robustness tricks.** Reward terms: wrist SE(3)+velocity, finger imitation (exp, position-weighted), smoothness (joint power = velocity × torque), object 6-DoF pose + velocity following, and a **contact-force reward gated on the MoCap hand-object distance being below a threshold**. Robustness machinery: (a) measured to tolerate **up to 1.5 cm** of input noise; (b) **physics relaxation curriculum** — start with zero gravity + high friction, restore real physics gradually; (c) reference-state initialization at random **non-colliding** trajectory states; (d) **early termination when grasping is indicated but contact forces are zero** — that's a contact-timing consistency check used as a training signal. Results: 8.60° rotation / 0.49 cm translation error, 58.1% single-hand / 39.5% bimanual success vs 4.6%/0.0% for retarget-only.

## D. Contact-timing / schedule estimation from noisy trajectories

**Heuristic stack (what everyone actually ships, none of it packaged as a library):**
1. EMA-smooth the 3D hand keypoints to kill jitter.
2. Compute min Euclidean distance between hand anchor points and the object surface per frame.
3. **Dual-threshold + hysteresis** on the smoothed distance signal (enter contact at `d < d_on`, exit at `d > d_off`, `d_off > d_on`) — prevents chatter around the boundary.
4. Add a relative-velocity gate: contact requires small tangential relative velocity as well as small distance (this is GeneOH's temporal component, reused as a classifier).
5. Frame-to-frame smoothing / morphological open-close on the binary contact mask to drop sub-N-frame spurious segments and fill sub-N-frame gaps.
6. Set `d_on` from the expected accuracy of the object pose tracker, not from a fixed constant.

Described piecemeal in: **DexFlow** (arXiv:2505.01083, dual-threshold contact maps + frame-to-frame smoothing; no code), **HOWTransfer** (arXiv:2606.10743, temporal contact interval localization → grasp hypotheses, 86% success; no code), **TouchMap-OR** (arXiv:2605.17638), and **Kinematic Motion Retargeting for Contact-Rich Anthropomorphic Manipulations** (ACM TOG 2025, https://dl.acm.org/doi/full/10.1145/3723872 — paywalled, 403'd on me).

**Learned contact classifiers:**
- **Hand-Object Contact Detection using Grasp Quality Metrics** (Nguyen & Cosgun, HRI'25, arXiv:2501.06987) — **takes exactly your input** (object + hand pose), computes grasp quality metrics as features, classifies contact. **~90% accuracy on DexYCB.** No code, but it's a small paper you can reimplement in a day — and it's the direct bridge between sections B and D.
- **100DOH hand_object_detector** (CVPR 2020 Oral) — https://github.com/ddshan/hand_object_detector, **MIT**, two pretrained models (`handobj_100K`, `handobj_100K+ego`). Predicts hand box + **contact state** (no contact / self / other-person / portable object / stationary object) + object box. Image-space only, so useless unless V2D also gives you video.
- **Hand-Object Contact Prediction via Motion-Based Pseudo-Labeling and Guided Progressive Label Correction** (BMVC 2021) — the right conceptual framework if your contact labels themselves are noisy: bootstrap from motion-based pseudo-labels, then progressively correct.

**How contact labels get consumed downstream:** as an RL reward (ManipTrans contact-force reward + zero-force termination; DexMachina masked-L2 contact reward; DexMan attraction reward; PhysHOI contact graph reward), as a retargeting constraint (switch between free-motion retargeting and contact-constrained IK when `d < threshold` — DexFlow), and as an optimization gate (CHOIR's contact cache confidence gates from proximity + normal compatibility + temporal persistence).

## Ranked: what I'd actually use for contact repair in 6 weeks

**Tier 1 — do these, in this order**

1. **Build the heuristic contact-schedule extractor yourself (2–3 days).** EMA + distance + relative-velocity gate + hysteresis + temporal morphological cleanup. It is the baseline every other item is measured against, and it's the only thing guaranteed to be done on time. Validate it against the grasp-quality-metric classifier idea from arXiv:2501.06987.

2. **Re-implement DexGraspNet's energy on the Dex3 URDF as a per-frame projector (3–5 days).** `E_fc + 100·E_dis + 100·E_pen + 10·E_spen + 1·E_joints`, Adam, initialized at your retargeted pose, trust region on the wrist, only active on frames the schedule says are in contact. Highest value per hour in this whole list because it operates on the *robot* hand, which is where your errors actually cost ADD-AUC. Source: https://github.com/PKU-EPIC/DexGraspNet/blob/main/grasp_generation/utils/energy.py (CC BY-NC 4.0 — check challenge rules).

3. **Put DexMan's contact-prior attraction reward in the policy (2–3 days).** 27.4% → 7.2% ablation. This moves part of the repair burden out of preprocessing and into training, where it's robust to residual data error. Pair it with **ManipTrans's zero-contact-force termination** and **physics relaxation curriculum** (zero gravity + high friction early) — both are ~20 lines each and directly buy noise tolerance.

4. **GeneOH Diffusion as the kinematic denoiser on the MANO/keypoint side (~1 week).** MIT, weights released, purpose-built for exactly "noisy hand motion + known object pose → clean HOI," and it beats TOCH by ~50% on penetration metrics on HOI4D zero-shot. Risks: manopth dependency, GRAB-domain prior, ARCTIC support still a repo TODO, and its stated assumption that object poses are accurate. Run it *before* retargeting.

**Tier 2 — if Tier 1 lands early**

5. **DexMachina's object-aware replay post-process** — freeze the object, replay retargeted joints in sim, resolve penetrations, extract feasible references. Cheap, and it's the step the authors found necessary. https://github.com/MandiZhao/dexmachina (MIT).
6. **DexMan's stable-configuration sampling** — perturb ±45°, simulate, keep the stable config closest to the original. One afternoon, 98% stability.
7. **A validation gate, not a repairer:** penetration < 2 mm + 6-direction gravity shake with < 2 cm displacement, in Isaac Lab with per-fingertip `ContactSensor`s (remember the `force_matrix_w` regex gotcha). Or run **DexGraspBench** in MuJoCo if you want analytic force-closure numbers for free.
8. **GenDexGrasp contact-map transfer** if the 5-finger MANO → 3-finger Dex3 correspondence turns out to be the actual bottleneck. Pretrained ckpts exist; no license file, so check before shipping.

**Tier 3 — read, don't integrate**

9. **CHOIR's loss recipe** (soft contact cache with normal-compatibility + temporal-persistence gating; 5 mm penetration dead zone) — reimplement the ideas into your own optimizer.
10. **ContactOpt** — MANO-only, archived, >60 s/frame. Only worth it for a final polish pass on a handful of sequences.
11. **SpringGrasp** — if object geometry uncertainty (not pose noise) turns out to be the dominant failure mode.

**Do not use:** TOCH (no weights), QuasiSim (24 h+ per trajectory), DECO/BSTRO/POSA/HOT (body-scale, image input, wrong granularity), HOLD/DiffHOI/HOISDF (reconstruction, not refinement), Dex-Net (Python 2), GraspIt! (legacy).
