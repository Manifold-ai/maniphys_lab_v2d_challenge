## 1. Repo structure, workflows, and the actual G1 configs

### Layout
```
source/isaaclab/          # core: envs, managers, actuators, controllers, devices, sim
source/isaaclab_assets/   # ArticulationCfg constants (robots/*.py)
source/isaaclab_tasks/    # manager_based/** and direct/** task registrations
source/isaaclab_rl/       # rsl_rl / rl_games / skrl / sb3 wrappers
source/isaaclab_mimic/    # data generation (MimicGen port)
```

**Manager-based vs direct** (https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/task_workflows.html):
- Manager-based: `isaaclab.envs.ManagerBasedEnv` / `ManagerBasedRLEnv` + `ManagerBasedRLEnvCfg`, composed of `ObservationManager`, `ActionManager`, `RewardManager`, `TerminationManager`, `EventManager`, `CommandManager`, `CurriculumManager`, addressing assets via `SceneEntityCfg`. Docs: *"more modular and allows different components of the environment to be swapped out easily."*
- Direct: `DirectRLEnv` / `DirectRLEnvCfg`, `DirectMARLEnv` / `DirectMARLEnvCfg`. Docs: *"more efficient and allows for more fine-grained control over the environment logic"*, better when *"scaling up training tremendously"*, and allows torch.jit / Warp kernels.

Every G1 env that ships is **manager-based**. BeyondMimic is also manager-based. Recommendation: stay manager-based unless you measure a manager-overhead problem.

### Cost of adding a rigid object + dexterous-hand collisions
No published A/B number exists. What the code tells you about the levers:

1. **PhysX GPU buffers.** Defaults (`source/isaaclab/isaaclab/sim/simulation_cfg.py`): `gpu_max_rigid_contact_count=2**23`, `gpu_max_rigid_patch_count=5*2**15` (163,840), `gpu_found_lost_pairs_capacity=2**21`, `gpu_found_lost_aggregate_pairs_capacity=2**25`, `gpu_total_aggregate_pairs_capacity=2**21`, `gpu_collision_stack_size=2**26`, `gpu_heap_capacity=2**26`, `gpu_max_num_partitions=8`. Dexsuite overrides `gpu_max_rigid_patch_count = 4 * 5 * 2**15` = **655,360, a 4× bump**, purely because of finger–object contact patches. If you don't raise it you get buffer-overflow warnings and dropped contacts.
2. **`replicate_physics=False`** in dexsuite (needed for per-env object variety) disables PhysX's fabric replication fast path — a real per-env cost at spawn and in the broadphase.
3. **Object solver iterations.** Dexsuite objects use `solver_position_iteration_count=16, solver_velocity_iteration_count=0` — 2× the robot's 8, applied per object.
4. **`bounce_threshold_velocity`** dropped from the 0.5 default to 0.01.
5. **Structural**: 14 extra articulation DoF, ~16 extra links per robot (8 per hand incl. palm), and — the expensive part — contact pairs between 6 finger colliders and the object at 200 Hz.

Empirically, Isaac Lab's own two reference points bracket it: Shadow (24-DoF hand + 1 cube, fixed base, convex colliders) runs 8192 envs at 170K train-FPS ≈ **20.8 env-steps/s/env** on a 4090; G1 rough (37 DoF, minimal colliders, rough terrain + height scanner) runs 4096 at 82K ≈ **20.0 env-steps/s/env**. A floating-base 43-DoF G1 + Dex3 + one object with self-collision on will land below both — plan for **roughly 2–4× the per-step cost of `Isaac-Velocity-Rough-G1-v0`** and halve `num_envs` to 2048 if VRAM or patch count becomes the bottleneck. Measure with `scripts/benchmarks/benchmark_non_rl.py` before committing.

Datagen timing anchor from the docs (`docs/source/overview/imitation-learning/teleop_imitation.rst`): G1 locomanip Mimic generation of 1000 demos = **18–40 min at 65–82% success (18 min on an RTX 6000 Ada @82%)**; BC training 2000 epochs ≈ 40 min on the same GPU, 75–85% rollout success.

### Joint index scrambling (practical trap)
PhysX reorders joints by articulation DFS, not URDF order. Unitree's own code hard-codes the resulting map for the 43-DoF G1+Dex3:
`unitree_sim_isaaclab/tasks/common_observations/dex3_state.py:111`
```python
gripper_joint_indices=[31, 37, 41, 30, 36, 29, 35, 34, 40, 42, 33, 39, 32, 38]
```
i.e. the 14 hand joints sit at articulation indices 29–42 but in a permuted order. Always resolve by name via `SceneEntityCfg(..., joint_names=[...])` or `asset.find_joints(...)`; never slice by assumed index.

### Isaac Lab issues
- **#4037** *"[Question] Possibility of replacing Unitree G1 USD in IsaacLab with Unitree's official USD"* — user reports IsaacLab's `g1.usd`/`g1_minimal.usd` *"have different configurations, especially the waist position, compared to the official USD files released by Unitree"*, blocking hardware deployment; swapping in Unitree's official `ArticulationCfg` made `Isaac-Velocity-Flat-G1-v0` fail to converge in the default 1500 iterations. No maintainer fix.
- **#2231** *"[Bug Report] convert_mjcf.py not working for G1"* (closed).
- **#3943** *"[Bug Report] Merge fixed joints parameters doesn't work"*, **#557** *"URDF converter seems broken when set merge_joints?"*, **#543** — URDF→USD conversion gotchas.
- **#3054** *"Hands/objects penetrating through each other during G1 teleoperation"* — G1 + Inspire, Isaac Lab 2.2 / Isaac Sim 5.0, AVP hand tracking, SDF collision meshes on objects; solver iterations and dt changes did not fix it. No confirmed resolution.
- **#4151** *"Very long 10+ minute load time"*, **#7750** BeyondMimic/ProtoMotions G1 tracker → MuJoCo transfer.

### Collision / conversion guidance actually in the docs
`docs/source/how-to/simulation_performance.rst`:
- Remove colliders from links that don't matter (Anymal-C keeps only knees + feet). This is exactly what `g1_minimal.usd` does.
- *"an SDF mesh collider will be more expensive than a simple sphere"*; primitives beat meshes.
- **The CPU-fallback trap**: `[Warning] [omni.physx.cooking.plugin] ConvexMeshCookingTask: failed to cook GPU-compatible mesh, collision detection will fall back to CPU.` — triggered by high-aspect-ratio convex hulls, which is exactly what thin Dex3 finger phalanges produce. Workaround: bounding-cube approximation, or static triangle-mesh colliders for non-dynamic geometry. **Watch for this specifically on the Dex3 fingers** — one bad hull silently tanks the whole run.
- Cylinder/cone colliders get special smooth-contact handling at a perf cost; disable with stage settings `--/physics/collisionApproximateCylinders=true` and `--/physics/collisionApproximateCones=true`.
- Gripper contact/grasp tuning guide: omni_physics `dev_guide/guides/gripper_tuning_example.html`.

### Self-collision
Every shipped G1 cfg sets `enabled_self_collisions=False`. **BeyondMimic sets `enabled_self_collisions=True`** and imports the URDF directly with `sim_utils.UrdfFileCfg(..., replace_cylinders_with_capsules=True, joint_drive=PDGainsCfg(stiffness=0, damping=0))`, letting the `ImplicitActuatorCfg` own the gains. For a Dex3 task you need self-collision on at least between hand and torso/object, which is where the convex-hull quality of the finger meshes starts to matter.

Use **`G1_29DOF_CFG`** as your starting articulation — it already resolves to the 43-DoF G1 + Dex3-1 USD — but **replace the `waist`/`arms` stiffnesses (5000/3000) and the `hands` `effort_limit=300`** with BeyondMimic-style derived gains and the real 1.4/2.45 N·m finger limits. Consider importing `g1_29dof_with_hand_rev_1_0.urdf` directly (BeyondMimic's `UrdfFileCfg` route) so you control the collider generation.
2. Copy BeyondMimic's `tracking_env_cfg.py` structure (MotionCommand + anchor/body pos/ori/vel exp rewards + asymmetric policy/critic groups + z-only termination), then add (a) 14 Dex3 joints to the action term, (b) a `RigidObjectCfg` for the manipulated object, (c) an object-pose tracking reward, (d) finger-object contact terms via `ContactSensorCfg`.
3. Budget: start at **2048 envs**, `sim.dt=1/200`, `decimation=4`. Raise `gpu_max_rigid_patch_count` to at least `4*5*2**15` and `gpu_found_lost_pairs_capacity` alongside it. Grep the startup log for the `ConvexMeshCookingTask ... fall back to CPU` warning on the finger links before you trust any FPS number.
4. rsl_rl with `obs_groups={"actor":["policy"],"critic":["policy","privileged"]}` is the right default; rl_games only if you need LSTM+asymmetric together in a well-trodden config.
5. `isaaclab_mimic` is usable for Dex3 (`LocomanipulationG1MimicEnv` proves the 28-dim wrist-pose + 7+7 finger action layout works end to end) — but it's a *demo-generation* path (`num_envs=1`, Pink IK, BC), orthogonal to RL tracking. Mine it for the retargeting stack and the Dex3 URDF/USD paths, not for the training loop.
