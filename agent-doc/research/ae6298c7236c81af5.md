# 第一部分:六个指标的精确定义

CHORD 论文本身**没有给这些指标的公式**。原文只有一句:"We adopted standardized metrics (AUC from Dexmachina, SP-SR from SPIDER, MP-SR from ManipTrans). In addition ... articulated joint position error (JPE, °), multi-object relative position error (RPE, cm), and keypoint mean per-frame pose error (MPPE, cm)."(https://arxiv.org/html/2607.00033v2 §4.1)。所以定义必须回到源论文和源代码。

**先纠正一个流传的错误**:网上的摘要工具会把 SP-SR 读成 "Single-Phase Success Rate"、MP-SR 读成 "Multi-Phase Success Rate"、JPE 读成 "Joint Position Error(机器人关节)"。都是错的。CHORD **v1** 把这个指标直接写作 `MT-SR`:"area under the object-tracking-error curve (AUC) from DexMachina [49], success rate from SPIDER (SP-SR) [29], and success rate from ManipTrans (**MT-SR**) [15]"(https://arxiv.org/html/2607.00033v1)。v2 才改名成 MP-SR。JPE 是**物体的** articulated joint 角度误差,单位是度。

## 1. AUC = DexMachina 的 ADD-AUC ✅ 已验证(代码级)

**论文层面**(https://arxiv.org/html/2505.24853v1 §B.4 脚注,逐字):

> "ADD stands for Average Distance, AUC stands for Area Under Curve, we don't use ADD-S because we have the exact matching targets from the demonstration metric with the key difference that we compute ADD for each object part separately (to accommodate articulated objects) and average ADD results before computing AUC."

**代码层面**(https://github.com/MandiZhao/dexmachina/blob/main/dexmachina/eval/compute_add.py):

```python
# 1) 每个 object part 采样 num_samples=500 个 mesh 顶点(convexify=True, disable_collision=True, gravity=0)
demo_verts = obj.transform_part_vertices(part_verts[part], part)   # 用 demo_state 的位姿
obj_verts  = obj.transform_part_vertices(part_verts[part], part)   # 用 rollout obj_state 的位姿

# 2) 逐顶点 L2(米),对顶点取均值 = 该帧该 part 的 ADD
dist = torch.norm(demo_verts - obj_verts, dim=-1)
dist = torch.mean(dist, dim=-1)

# 3) AUC
def compute_auc(mean_add, thresholds):
    accuracies = [np.mean(mean_add < thres) for thres in thresholds]
    x_values = np.linspace(0, 1, len(thresholds))
    return float(np.trapz(accuracies, x=x_values))

thresholds = list(np.arange(0.01, 0.1, 0.01))     # 1,2,…,9 cm,共 9 个
auc["overall"] = float(np.mean(list(auc.values())))   # ← 各 part 的 AUC 再平均
```

文档 https://github.com/MandiZhao/dexmachina/blob/main/dexmachina/eval/eval.md 逐字复述同一流程。

**要点:**
- **是 ADD 不是 ADD-S** —— 顶点一一对应,没有最近邻匹配。物体对称性**不**被宽恕。
- ADD 是 mesh 顶点距离,位置误差和旋转误差耦合,旋转误差被物体尺寸线性放大。大物体的旋转误差惩罚天然更重。
- x 轴被 `linspace(0,1,9)` 归一化,AUC ∈ [0,1],梯形法则展开是 `(1/8)(0.5·a₁ + a₂+…+a₈ + 0.5·a₉)`。
- **AUC = 1.0 要求几乎所有帧 ADD < 1 cm。** CHORD 的 0.918 意味着绝大多数帧压在 1–2 cm。
- **对照的是 reference 物体轨迹**(代码变量名 `demo_state`),不是独立 GT。

**⚠️ 论文与代码不一致(未解决)**:论文说"average ADD results **before** computing AUC"(先跨 part 平均 ADD,再算一条 AUC);代码是 `auc["overall"] = mean(per-part AUC)`(**先各 part 算 AUC 再平均**)。单 part 时等价,part 之间误差差距大时不等价——先平均 ADD 会让好 part 把差 part 拉上来,先算 AUC 再平均是两条独立及格线。V2D 有大量 articulated(2 part)和 multi-object 任务,这个差别会显性化。**CHORD 沿用哪一种,没有任何文档说明。**

**DexMachina 自己的评测协议**(§B.4 逐字):"For each method and task, we run 5 random seeds; each seed run saves a best policy checkpoint based on cumulative task reward, and each checkpoint is evaluated for 20 episodes." 它论文 Fig. 3 / Fig. 5 里 y 轴标 "success rate" 的那条曲线**就是 ADD-AUC 值本身**,不是别的成功率。

## 2. SP-SR = SPIDER success rate ✅ 已验证(论文 + 代码)

https://arxiv.org/html/2511.09484v2 §3.1,逐字:

> "For object tracking error, we compute per-step averaged rotation error `E_rot = (1/T) Σ_{t=1}^T arccos(2⟨q_obj,t, q_obj,t^ref⟩² − 1)` and position error `E_pos = (1/T) Σ_{t=1}^T ‖p_obj,t − p_obj,t^ref‖₂` ... We follow the same evaluation setting as ManipTrans and DexMachina, where we report task success **only concerning object motion**. Task success is defined using: (1) the rotation error **E_rot < 0.5** rad, and (2) the average per-step translation error **E_pos < 0.1** m."

```
E_rot = (1/T) Σ arccos( 2⟨q_obj,t , q_obj,t^ref⟩² − 1 )      [rad]
E_pos = (1/T) Σ ‖ p_obj,t − p_obj,t^ref ‖₂                   [m]

SP-SR success  ⟺  E_rot < 0.5 rad (≈28.65°)  AND  E_pos < 0.1 m
```

代码确认(`spider/postprocess/get_success_rate.py`):`pos_err_threshold=0.1`、`quat_err_threshold=0.5`、`success = (obj_pos_err <= pos_err_threshold) & (obj_quat_err <= quat_err_threshold)`(代码是 `<=`,论文是 `<`,无实质差别)。

**完全不看手**。这是六个指标里最宽松的,所以 CHORD Table 1 里 SP-SR 永远 ≥ MP-SR。**对照的是 reference 物体轨迹**。

**两个坑:**
1. **版本漂移**:SPIDER v1 写的是 `E_pos < 3 cm`,v2 改成 `0.1 m`(放宽 3.3×),但两版的大规模结果表数字完全没变(只有消融 Table 1 改了)。CHORD(2026-06)晚于 v2 且用了 release 的代码,**几乎肯定是 0.1 m,但 CHORD 从没明说过**。
2. **bimanual 分支做了 mean-centering**:SPIDER 源码在 `embodiment_type == "bimanual"` 时先 `pos_object_traj -= pos_object_traj.mean(axis=0)`(参考轨迹同理)再算 L2,也就是**丢弃了常数世界系偏移**,变成形状/轨迹相似度而非绝对位置误差。单手分支用绝对位置。CHORD 复现时是否保留这个行为,未知。

## 3. MP-SR = ManipTrans success rate ✅ 已验证(论文)

https://arxiv.org/html/2503.21860v1 §4.1,逐字:

> "1) Per-frame Average Object Rotation and Translation Error: `E_r = (1/T) Σ (p_rot_ô^t · (p_rot_o^t)^{-1})` and `E_t = (1/T) Σ ‖p_tsl_ô^t − p_tsl_o^t‖²₂`. Errors E_r and E_t are reported in degrees and centimeters.
> 2) Mean Per-Joint Position Error (in cm): `E_j = (1/(T·F)) Σ_t Σ_{f=1}^F ‖j_{d_f}^t − j_{h_f}^t‖²₂`
> 3) Mean Per-Fingertip Position Error (in cm): `E_ft = (1/(T·M)) Σ_t Σ_{ft=1}^M ‖t_{d_ft}^t − t_{h_ft}^t‖²₂` ... Here, M equals 5 for single-hand tasks and **10 for bimanual tasks**.
> 4) Success Rate (SR): A tracking attempt is deemed successful if E_r, E_t, E_j, and E_ft are **all** below the specified thresholds: **30°, 3 cm, 8 cm, and 6 cm**, respectively. For bimanual tasks, the trajectory is considered failed if **either hand** fails to meet these conditions."

| 项 | 对照物 | 阈值 |
|---|---|---|
| E_r | 物体旋转 vs reference | < 30° |
| E_t | 物体平移 vs reference | < 3 cm |
| E_j | 机器人手 21 个 keypoint vs **人手 MANO keypoint** | < 8 cm |
| E_ft | 指尖 vs **人手指尖**,单手 M=5 / 双手 M=10 | < 6 cm |

**四条全中才算成功,双手任一只手不达标整条判失败。**

关键性质:**这是六个指标里唯一把手部 kinematic 保真写进成功条件的**,而且 E_j / E_ft 对照的是**人手**(j_h),不是 retarget 后的机器人参考——跨形态下这里没有"干净 GT"可言,人手就是参照。ManipTrans 在机器人手上手工选 F=21 个 keypoint 对应 MANO 的指尖/掌心/指节(§4.2)。

**注**:论文里 E_t/E_j/E_ft 写的是 `‖·‖²₂`(平方 L2)但单位标 cm,这是排版失误,应读作 L2 距离。论文未澄清。

**对 Track 2 的直接后果**:Dex3 只有 3 指、每手 7 DoF,MANO 有 5 指 21 关节,E_j / E_ft 在这种形态差下如何对应,**CHORD 和挑战页都没有任何说明**。这是 Track 2 最实际的定义空洞之一。

CHORD 自己的消融也印证了这条指标的性质:"No Contact" 变体 AUC 还有 0.774,MP-SR 掉到 0.612;Position-Only 变体 AUC 0.862、MP-SR 0.780。**MP-SR 一直掉得比 AUC 狠。**

> "Keypoints are defined as the 6 principal unit vectors (+X, +Y, +Z, -X, -Y, -Z) transformed to world space using the current and command object poses."

## 6. RPE ⚠️ 部分验证

CHORD 逐字:"**multi-object relative position error (RPE, cm)**"。即多物体之间的相对位置误差,对照 reference 的物体间相对位姿。单物体序列该项为 0/不适用。

repo 里对应 `relative_object_pos_error` / `relative_object_rot_error`,gating 阈值 `relative_object_proximity_threshold = 0.3`(demo 物体根距离 < 0.3 m 才激活),见 `commands/commands_cfg.py`。reward 侧公式在论文附录 B 给了:

```
r_relative(t) = m(t) · exp( −(e_p(t) · e_R(t)) / var_rel )
e_p(t) = ‖p_{1|0}(t) − p̄_{1|0}(t)‖₂
e_R(t) = d_geo( R_{1|0}(t), R̄_{1|0}(t) )
```

`m(t)` 是二值 mask,**只依赖 demo 的物体间距离,不依赖 policy 当前距离**——防止 policy 靠把物体拉远来规避这项。但 RPE **指标**本身是不是就是 `e_p` 的逐帧平均,论文没说。

**注**:JPE 和 RPE 都**不在** Track 2 的评分指标里。挑战页只列了 AUC、SP-SR、MP-SR、MPPE。

# 第二部分:CHORD 深度拆解

**arXiv 2607.00033**,NVIDIA,v1 2026-06-22,v2 2026-08-14,CC BY 4.0。21 位作者(Xinghao Zhu 一作,Yan Chang 为 project lead & 通讯)。https://arxiv.org/abs/2607.00033 · 项目页 https://nvidia-isaac.github.io/video_to_data/chord/

## 核心思想

不匹配 3D 接触**位置**,而是把人手和机器手的接触投影到**物体中心的 wrench space** 比较。

每个接触点 i 上,用多面体摩擦锥近似(d 条边,`num_friction_cone_edges = 8`),第 j 条边力诱导的 primitive wrench:

```
w^{i,j}_{h,k} = [ f^j_{h,k} , p^i_{h,k} × f^j_{h,k} ]ᵀ ∈ R⁶
```

拼成 wrench matrix `W_{h,k} ∈ R^{6×(c_{h,k}·d)}`。因为人手和机器手接触点数、顺序、形态都不同,矩阵没法直接比,所以用 **support function** 投到 b 个预采样单位方向 `B ∈ R^{6×b}` 上(`num_wrench_space_basis_samples = 512`):

```
σ_{h,k} = max_col( Bᵀ W_{h,k} ) ∈ R^b
```

reward 是把机器人的 σ_r 卡进人的 σ_h 的容差带 `[(1−β)σ_h, (1+β)σ_h]`(β = tolerance = 0.1):

```
r_cws^k = exp( −‖max(0, (1−β)σ_{h,k} − σ_{r,k})‖²₂ / v_cws
              −‖max(0, σ_{r,k} − (1+β)σ_{h,k})‖²₂ / v_cws )
```

因为指数核永远是正的,再加两个惩罚:`r_unintend^k`(σ_h=0 但 σ_r>0,即制造了人没有的接触)、`r_miss^k`(σ_h>0 但 σ_r=0,即漏掉了参考要求的接触)。

论文明确承认:"We do not recover the physically exact multi-contact feasible net-wrench polytope. Instead, our wrench representation defines directional capability per contact, and we compare the resulting support values as a guidance signal. Actuation feasibility is subsequently enforced by the simulator."

**噪声参考退化路径**:contact 估计不可靠时(RGB 重建),切到 reduced 目标

```
r_fc^k = (1/B) Σ_{b=1}^B 1[ σ_{r,k,b} > ε ]
```

最大化时等价于 force closure。代价是"relying on force-closure guidance reduces dexterity, as it prioritizes stable grasps over faithful imitation"。

## Reward 全表

总式:`r = r_task + r_imit + r_contact`

```
r_task     = exp( −Σ_k ‖x_t^{obj,k} ⊖ s_t^{obj,k}‖²₂ / var_obj ) + r_relative
r_relative = m(t) · exp( −e_object / var_rel )            # 见前文 RPE 节
r_imit     = exp( −‖x_t^robot − s_t^robot‖²₂ / var_imit )
r_contact  = r_cws + r_unintend + r_miss   (或 r_fc)
```

**repo 里的实际权重**(`tasks/v2d/v2d_hand_env_cfg.py::RewardsCfg`):

| term | weight | params |
|---|---|---|
| `contact_wrench_support_reward` | **+10.0** | tolerance 0.1, var 0.1 |
| `unintended_contact_penalty` | **−10.0** | |
| `missed_contact_penalty` | **−1.0** | |
| `termination_penalty` | **−100.0** | |
| `object_keypoints_tracking_exp` | 0.0(由 curriculum 接管,0 → 20.0) | var 0.1 |
| `hand_keypoints_tracking_exp` | 0.0(curriculum 定为 0.25) | var 0.1 |
| `hand_joint_pos_tracking_exp` | 0.0(curriculum 定为 0.25) | var 1.0 |
| `action_rate_l2` | −5e-3 | |
| `action_l1`(action_norm) | −2e-3 | |
| `force_closure` | **0.0**(默认关) | min_support 0.01 |

`force_closure` 的注释逐字:"an alternative to contact_wrench_support_reward for references whose contact positions/normals are noisy (e.g. monocular ego reconstructions). Enable it and zero the three contact terms above — **including their fixed_timestep_curriculum `rewards_*` params, which otherwise overwrite the weights on schedule**." 这是个容易踩的坑。

## Curriculum

`FixedTimestepCurriculum`,`num_steps_per_env = 24`:

```
timestep_schedule:  [2000, 3500, 5000, 6500, 8000, 9500, 11000, 12500, 14000, 15500]
VOC scale factor:   [1.0,  0.75, 0.5,  0.25, 0.1,  0.05, 0.025, 0.01,  0.0,   0.0  ]
object_keypoints:   [0.0,  0.1,  0.25, 0.25, 0.5,  0.5,  1.0,   1.0,   1.0,   20.0 ]
hand_keypoints:     0.25 (constant)
hand_joint_pos:     0.25 (constant)
contact_wrench:     10.0 (constant)
unintended:         −10.0 (constant)
missed:             −1.0 (constant)
```

论文强调的关键顺序:"stable training requires the **contact wrench reward to converge before decaying the VOC**"。

VOC(virtual object controller)本身继承自 DexMachina:每个刚体/articulated object 创建一个零动作维度的 control term,内部施加 curriculum 缩放的 PD wrench/effort,把物体拖着走,然后逐步撤力交给 policy。

## 观测空间

## 终止与 reset

终止(`tasks/v2d/mdp/terminations.py` + env cfg):
- `timestep_timeout`:`timestep_counter >= retargeted_horizon − 1`
- `hand_wrist_away_from_trajectory`,threshold **0.2**
- `object_away_from_trajectory`,repo 默认 **position 0.2 m / orientation 0.7 rad(= 40.1°)**

⚠️ **论文正文说的是 15 cm / 40°**:"A rollout succeeds if it completes the task without object-centric termination, defined by position error above 15 cm or rotation error above 40°." whole-body 那边 `_apply_contact_rewards()` 确实是 `object_pos_error = 0.15, object_quat_error = 1.0`。**两处对不上,记一笔。**

Reset:
- 每个 episode 从参考轨迹的**随机帧**开始
- 恢复物体 root pose/vel、articulated joint,恢复双腕 root pose/vel
- 手指初始化为参考姿态的"部分张开"版,插值因子 `U[0, 0.7]`(`reset_finger_openness = 0.7`)
- VOC scale 重置为 1.0,**20 步 warm-up** 后再进 curriculum
- 清空 raw action / prev action / wrist force & torque / finger target

"随机中途 reset + VOC 短暂全开"是它长时序能力的关键机制之一。

## 真机

随机游走噪声,6 个档位:

| Scale | wrist pos (mm) | wrist ori (°) | contact pos (mm) | contact normal (°) |
|---|---|---|---|---|
| 1 | 10 | 5 | 5 | 5 |
| 2 | 20 | 10 | 10 | 10 |
| 3 | 30 | 15 | 15 | 15 |
| 4 | 40 | 20 | 20 | 20 |
| 5 | 50 | 25 | 25 | 25 |
| 6 | 60 | 30 | 30 | 30 |

三种设定:(a) 只加手姿噪声 + wrench reward(模拟视频重建 + 触觉手套);(b) 手姿 + 接触都加噪 + wrench reward(纯视频重建);(c) 手姿 + 接触都加噪 + force-closure reward。

结论:手姿噪声容忍度尚可,性能缓降;接触也加噪后掉得明显;**噪声很大时 force-closure 反超 wrench matching**,因为严重损坏的 wrench support 会提供误导性监督。代价是 force-closure 降低灵巧度。

## 论文自陈的失败模式(§6)

1. 真机部署依赖 state-based observation(Vicon),没有 vision
2. 有效的 contact guidance 需要相对干净的 demo;噪声接触污染 reward,只能退到 force-closure 假设
3. object pose error 是个有缺陷的评价:有些任务不在乎精确摆放,有些任务小误差就功能性失败
4. (从 4.1)难任务——接触区域小、交互精细的——普遍需要更长优化

# 第三部分:方法谱系

## DexMachina(ICML 2026,arXiv 2505.24853)

Zhao Mandi, Yifan Hou, Dieter Fox, Yashraj Narang, Ajay Mandlekar\*, Shuran Song\*(Stanford + NVIDIA)。仅 v1,2025-05-30,CC BY 4.0。https://arxiv.org/abs/2505.24853 · 项目页 https://project-dexmachina.github.io/ · 文档 https://mandizhao.github.io/dexmachina-docs

**核心**:提出 "functional retargeting" —— 给一条 ARCTIC demo 和一对灵巧手,学 `π = argmin_θ Σ_t F(ĝ_t, g_t)`,跟踪**物体状态**(位置、旋转、关节角),不跟踪手姿。三个组件:

1. **VOC auto-curriculum**(headline):物体挂 **6 个 base 虚拟 DoF + 1 个 articulation 虚拟 DoF**,全部 PD 驱动,把物体拖着走;gains `(k_p, k_v)` 在**四项 reward 的滑动均值全部超阈值**时才指数衰减。`object.py::step` 里 `entity.control_dofs_position(demo_dofs[t+1])` over `dof_idxs = range(7)`。
2. **Hybrid action**:retarget 的 6-DoF 腕关节值作 base action + policy residual;手指用按限位归一化的**绝对**动作。
3. 辅助 reward。

**Reward**(§4.1–4.2 逐字):
```
d_pos = ‖ĝ_t^T − g_t^T‖₂ ;  d_rot = 2cos⁻¹(|⟨ĝ_t^R, g_t^R⟩|) ;  d_ang = ‖ĝ_t^J − g_t^J‖₂
r_task = exp(−β_pos d_pos) · exp(−β_rot d_rot) · exp(−β_ang d_ang)      ← 乘积,不是和
r_imi  = (1/K) Σ exp(−β_imi ‖x̂_i − x_i‖₂)
r_bc   = (1/J) Σ exp(−β_bc ‖q̂_i − q_i‖₂)
r_con  = (1/(2NK)) ( Σ_ij exp(−β_con D_left^{ij}) + Σ_ij exp(−β_con D_right^{ij}) )
r_t    = λ_task r_task + λ_imi r_imi + λ_bc r_bc + λ_con r_con
```
接触距离矩阵 `D = ‖C − Ĉ‖₂`,mask 不匹配时置 `d_max`,双方都无接触时置 0。

release 脚本的实际值:`task_rew_betas 10 1 5`(默认 20/5/20)、`-imi 0.3 -bc 0.3 -con 3`、`imi_wrist_weight 0.5`、`imi_wrist_pos_beta 10`、`imi_wrist_rot_beta 3`、`imi_fingertip_beta 20`、`bc_beta 500`、`contact_beta 10`(默认 30)、`hybrid_scales 0.1 1.0`(±10 cm / ±1 rad)。

**两个论文没提的惩罚项**(`envs/rewards.py`):force penalty(默认 0.1,`mean(max(‖F‖−500, 0))`)、action penalty(release 脚本 0.01,`mean(a²)`)。

**论文与代码不一致**:`r_imi` 默认路径(`exp_kpt_first=False`)算的是 `exp(−β·mean_i dist_i)`,即 **exp of mean**,不是论文写的 mean of exps;而且代码额外混了个论文公式里没有的腕项 `r_imi = λ·[w_wrist·r_wrist + (1−w_wrist)·r_fingertip]`。

**Curriculum(Algorithm 1)**:每次 PPO 迭代,对完成的 episode 算 `r̄_z = R_z / L_max`,`z ∈ {task, imi, bc, con}`,压进 deque 取均值 `μ_z`;`μ_z > σ_z ∀z` 时 `k_p ← k_p·φ_p`、`k_v ← k_v·φ_v`;`k_p ≤ 0.01` 时直接归零。release 配置:`--kp_init 80 --kv_init 5 --curr_rew_thres 0.6 0.01 0.01 0.01 --deque_len 30 --wait_epochs 100 --upper_ratios 0.9 0.9 1 --lower_ratios 0.8 0.8 1`。

**观测**(§B.2 只有一句"object states, joint targets, finger-to-object distances, and normalized hand-object contact forces",精确组成在代码里):
- 每手:`dof_target_pos`(ndof)、归一化 `dof_pos`(ndof)、`dof_vel`(ndof)、`kpt_pos`(n_kpts×3)、`wrist_pose`(7)
- 物体:`parts_pose`(7×n_links,ARCTIC n_links=2)、root ang vel(3)、root lin vel(3)、dof_pos(1)、`state_diff`(8)= `demo_state[t+goal] − [root_pos, root_quat, joint_qpos]` → 共 29 维
- 全局:归一化 episode phase `2·len_buf/max_len − 1`(1 维,常开);可选 `observe_tip_dist`(n_kpts×2×2)、`observe_contact_force`(`‖F‖×0.01`)
- 观测 clip 至 ±5.0,NaN 替换为 −5.0
- **没有 future reference window**;**不是 asymmetric actor-critic** —— wrapper 返回 `dict(policy=obs, critic=obs)`,`num_privileged_obs = None`

**动作**:`action_dim = 左 + 右`,每手 = 驱动关节数 − mimic 关节数,clip [−1,1]。目标经 mimic 乘子 → clamp 限位 → EMA(`action_moving_avg` 默认 1.0 即不平滑)→ Genesis PD 控制器的**关节位置目标**(非力矩)。Inspire gains:手指 kp 20 / kv 1 / force_range 50,腕旋转 kp 80 / kv 5。

**终止**:timeout;NaN;物体 root `z < table_height`;每 `early_reset_interval=5` 步检查 `cumulative_task_rew < 0.6 × elapsed` 则 reset。

## ManipTrans(CVPR 2025,arXiv 2503.21860)

Kailin Li, Puhao Li, Tengyu Liu, Yuyang Li, Siyuan Huang(BIGAI)。v1 2025-03-27。https://arxiv.org/abs/2503.21860 · CVF PDF https://www.openaccess.thecvf.com/content/CVPR2025/papers/Li_ManipTrans_Efficient_Dexterous_Bimanual_Manipulation_Transfer_via_Residual_Learning_CVPR_2025_paper.pdf · 项目页 https://maniptrans.github.io/

**核心**:两阶段残差。**Stage 1** 在纯手部数据(已有手部动作集 + 镜像 + 插值合成)上训一个**通用、无物体**的手轨迹 imitator `I`;**Stage 2** 冻结 `I`,对每个 manipulation primitive 训一个 residual `R`,执行动作 `a^t = a_I^t + Δa_R^t`(逐元素相加后 clip 到限位)。`R` 零均值初始化 + warm-up,起手接近恒等。训练时放松物理(零重力、高摩擦)和误差阈值,再退火。产出 **DexManipNet**:3.3K episodes / 61 tasks / 1.2K objects / 1.34M frames,约 600 条双手序列。

**观测**(三组):
- `s_prop`:`propObsDim = 13 + ndof*3`,keys `[q, cos_q, sin_q, base_state]`。`base_state` 13 维(pos 3 + quat 4 + lin vel 3 + ang vel 3)但**位置被置零**("ignore base position")
- `s_privileged`:`ndof + 13 + 5*4 + 3 + 1`,keys `[dq, manip_obj_pos, manip_obj_quat, manip_obj_vel, manip_obj_ang_vel, tip_force, manip_obj_com, manip_obj_weight]`。`manip_obj_pos` 和 `manip_obj_com` 相对腕表示;`tip_force` = 5 接触体 × 4(3 向量 + 模长);`manip_obj_weight` = mass × |g_z|
- `TARGET_OBS_DIM`(每两手):`(128 + 5 + (3+3+3+4+4+3+3 + (n_bodies−1)*9 + 3+3+3+4+4+3+3 + n_bodies) * obs_future_length) * 2`。顺序:`delta_wrist_pos, wrist_vel, delta_wrist_vel, wrist_quat, delta_wrist_quat, wrist_ang_vel, delta_wrist_ang_vel, delta_joints_pos, joints_vel, delta_joints_vel, delta_manip_obj_pos, manip_obj_vel, delta_manip_obj_vel, manip_obj_quat, delta_manip_obj_quat, manip_obj_ang_vel, delta_manip_obj_ang_vel, obj_to_joints, gt_tips_distance, bps`。BPS = 128 点(`grid_sphere`,radius 0.2),`gt_tips_distance` = 5
- **`obsFutureLength: 1`** —— reference window 只有**下一帧**
- Inspire(ndof 12,n_bodies 18)双手实例:proprioception 98、privileged 98、target 700;residual 网额外吃冻结 imitator 采样动作 `(6+ndof)*2 = 36`
- **不是真正的 asymmetric actor-critic**:`lib/rl/network_builder_residual_bih.py` 里共享 `actor_mlp` 同时接 `mu` 和 `value`,并且显式 `raise NotImplementedError("central_value not implemented")`。"privileged" 只是分组标签。Encoder `SimpleFeatureFusion`(hidden_depth 3, hidden_dim 512, output_dim 256, swish)→ MLP `[256,512,128,64]` ELU,`normalize_input: True`

**动作**:§3.1 逐字 —— "comprises the target positions of each dexterous hand's joint `a_q^t ∈ R^K` for PD control, and the **6-DoF force** `a_w^t ∈ R^6` applied to the robotic wrist"。`numActions = 6 + n_dofs` 每手,双手翻倍。完整动作向量 = `[base_action ‖ residual_action]`,中点切分,`residual_action = actions[:, split:] * 2` → **残差范围 [−2, 2]** 而 base 是 [−1, 1]。

手指:`dof_pos = base + residual` → clamp(−1,1) → scale 到限位 → EMA(README 用 **0.4**)→ clamp → `set_dof_position_target_tensor`。
腕(浮动基,**力控不是位控**):
```python
rh_force  = base[:,0:3]*dt*translation_scale*500 + residual[:,0:3]*dt*translation_scale*500
rh_torque = base[:,3:6]*dt*orientation_scale*200 + residual[:,3:6]*dt*orientation_scale*200
```
`translationScale: 1.0`、`orientationScale: 0.1`。另有 `usePIDControl` 模式,代码注释说是 "reference only, not our main method"。

**Reward**:
Stage 1 `r_I = w_wrist·r_wrist + w_finger·r_finger + w_smooth·r_smooth`,`r_finger = Σ_f w_f exp(−λ_f ‖j_{d_f} − j_{h_f}‖²₂)`。Table 5 给每指四段(proximal/intermediate/distal/tip)的 `(w_f, λ_f)`:Thumb 0.5/0.3/0.3/0.9 与 50/40/40/100;Index …/0.8 与 …/90;Middle …/0.75 与 …/80;Ring 与 Pinky …/0.6 与 …/60。"if a dexterous hand lacks a specific finger or joint (e.g., the Inspire Hand does not have distal joints), the corresponding parameters are set to zero."

Stage 2 追加 `+ 5.0*reward_obj_pos + 1.0*reward_obj_rot + 0.1*reward_obj_vel + 0.1*reward_obj_ang_vel + 1.0*reward_finger_tip_force`,其中 `reward_obj_pos = exp(−80·d)`、`reward_obj_rot = exp(−3·|Δθ|)`,接触项用 `contact_range = [0.02, 0.03]` 的线性权重掩码指尖力。

## SPIDER(arXiv 2511.09484)

Chaoyi Pan, Changhao Wang, Haozhi Qi, Zixi Liu, Homanga Bharadhwaj, Akash Sharma, Tingfan Wu, Guanya Shi, Jitendra Malik, Francois Hogan(Meta FAIR + CMU)。v1 2025-11-12,v2 2026。https://arxiv.org/abs/2511.09484 · 项目页 https://jc-bao.github.io/spider-project · 文档 https://facebookresearch.github.io/spider/ · **未找到任何同行评审 venue**。

**⚠️ 关键认知:SPIDER 不是 RL,不产出 policy。** 它是**离线采样式轨迹优化**(MPPI 族),在 GPU 物理仿真器里跑,输出是**开环控制序列**。没有 policy 网络,没有 observation 向量,没有 PPO。RL 只在 §4.2 作为**下游应用**出现。

**方法**三件套:
1. **annealed sampling kernel** —— 搜索半径随优化迭代 i 和 horizon index h 双向收缩:`Σ^i_h = exp(−(N−i)/(β₁N) − (H−h)/(β₂H)) · I`
2. **virtual contact guidance** —— 对第 k 个接触对,用相对位置 `^robot p_{k,t}^object = p^robot_{k,t} − p^object_{k,t}`,指示 `c_{k,t} = 1(‖^robot p_{k,t}^{object,ref}‖₂ ≤ ε_contact)`,约束 `c_{k,t}‖^robot p_{k,t}^object − ^robot p_{k,t}^{object,ref}‖²₂ ≤ η_i`,`η_i → ∞` 当 `i → N`。论文明确把它和 DexMachina 的**绝对**物体约束 `‖p^obj − p^obj,ref‖²₂ ≤ η` 区分开。接触过滤器:接触时长 < `t_c,min` 或接触点漂移 > `d_c,max` 判为不稳定,该虚拟约束关闭
3. **robustification** —— `J_rob(U) = max_{d∈D} J(U,d)`,实际按 minibatch `max_{k≤K} J(U_j, d_k)`,`D` 涵盖接触 margin、摩擦系数、物体质量

**成本函数**(Eq. 1a):
```
min_U  ‖x_T − x_T^ref‖²_{Q_T} + Σ_{t=0}^{T-1} ( ‖x_{t+1} − x_{t+1}^ref‖²_{Q_t} + ‖u_t‖²_{R_t} )
s.t.   x_{t+1} = f(x_t, u_t, t),  x ∈ X, u ∈ U
```
`Q_t = diag({q_robot, q_object})`。论文没给权重数值;代码 `spider/config.py` 默认:`base_pos_rew_scale=1.0, base_rot_rew_scale=0.3, joint_rew_scale=0.003, pos_rew_scale=1.0, rot_rew_scale=0.3, vel_rew_scale=0.0001, terminal_rew_scale=1.0`,**`contact_rew_scale=0.0`(接触 reward 默认关闭)**。

**IK 预处理**(App. A.1):每手 21D keypoint(3D 指尖 + 6D 腕姿,来自 MANO),
```
L_IK = Σ_i ‖p_i^robot − p_i^human‖² + 0.1‖R_wrist^robot − R_wrist^human‖²_F
```

## Human2Sim2Robot(CoRL 2025,arXiv 2504.12609)

Tyler Ga Wei Lum\*, Olivia Y. Lee\*, C. Karen Liu, Jeannette Bohg(Stanford)。正式标题 "Crossing the Human-Robot Embodiment Gap with Sim-to-Real RL using One Human Demonstration"。v1 2025-04-17,v3 2025-08-16。https://arxiv.org/abs/2504.12609 · 项目页 https://human2sim2robot.github.io/

**核心**:一段单目 RGB-D 人类视频,只抽两样东西 —— (a) 物体 6D pose 轨迹 → object-centric、embodiment-agnostic 的稠密跟踪 reward;(b) **一帧** pre-manipulation 手姿 → IK 重定向后作为 RL 初始状态分布的种子。没有逐帧 action label,**没有手部跟踪 reward**,没有任务特定 reward 调参。

管线:Kiri Engine(物体网格)+ 3D Scanner App(场景网格);**FoundationPose** 做 6D pose(依赖 **SAM 2** 掩码);**HaMeR** 出 MANO 手姿,ICP 深度对齐;**cuRobo** 做两步 IK 重定向(第一步臂对齐机器人中指关节到人的中指关节,第二步手指关节对齐指尖)。

Pre-manipulation 时刻 `τ = t₀ − t_offset`,`t₀` = 物体速度首次超过 **`v_min = 5 cm/s`** 的时刻,`t_offset = 30`(30 Hz 下 1 秒)。

**观测**(§3.2):
```
o_t = [ q_t , q̇_t , X_t^fingertips , x_t^palm , X_t^obj , X_{τ+t}^target ]
```
物体位姿**用 3 个 anchor point 的位置表示,不用四元数**。KUKA iiwa 14(7)+ Allegro(16)= N_joints 23、N_fingers 4、N_anchor 3 → `o_t ∈ R⁷⁹`(23+23+12+3+9+9)。**论文没写 79,这是我的算术。**

**策略观测里明确没有**:物体线/角速度、接触/力、时间步、任何触觉。训练时物体位姿观测加噪。

**真 asymmetric actor-critic**(§App. E):`s_t = [o_t, v_t, ω_t, t, f_t^dof, F_t^fingers]` → `s_t ∈ R¹¹³`(推算)。**注意这是 asymmetric critic,不是 teacher-student 蒸馏**,没有第二阶段。

**动作**:
```
a_t = [ x_t^palm-target(3) , r_t^palm-target(3, Euler) , x_t^pca-target(5) ] ∈ R¹¹
```
**绝对目标,不是残差**。16 个 Allegro 关节压到 **5 维 PCA 子空间**。控制栈:policy **15 Hz**(66.7 ms)→ geometric fabric 控制器 **60 Hz** → 关节 PD 目标,硬件 PD **200 Hz**。仿真里每个动作步 = **8 个 8.33 ms 子步 → decimation 8,物理 120 Hz**。

**Reward —— 只有一项**:
```
r_t = exp( −α · d(T^target_{τ+t}, T^obj_t) )
d(T₁,T₂) = Σ_{i=1}^{N^anchor} ‖ T₁ k_i − T₂ k_i ‖
```
`α = 10`,`N_anchor = 3`,`k₁=[L,0,0], k₂=[0,L,0], k₃=[0,0,L]`(物体局部系),**L = 0.2 m**,所有任务同一个 L。旋转对称物体会删掉垂直于对称轴的 anchor(App. C),同时改变 reward 和观测。

**没有接触 reward、没有手部跟踪 reward、没有 action-rate 惩罚、没有能量惩罚、没有成功 bonus、没有 curriculum。** 这是论文的核心主张。

**终止**(`D_max = 0.25 m`):`d(T^target, T^obj) > D_max`;或 `‖x^palm − x^obj‖ > D_max`;或 `τ + t > T`。

**初始状态分布**(v3 App. D,**相比 v2 收窄了**):`T^obj_1 = T^target_τ · T^random`,v3 **只采 yaw**,`y ~ U(−20°, 20°)`,roll/pitch 固定 0;平移 `x,y ~ U(−0.1, 0.1) m`,`z = 0`。(v2 采完整 roll/pitch/yaw 和三维平移。)腕放在 `T^obj_1 · T^relative`,`T^relative = (T^target_τ)^{-1} T^wrist`,加小噪声,臂 IK 走 cuRobo。

**算法/框架**:**PPO(rl-games)+ IsaacGym**。lr 5e-4、**γ = 0.998**、entropy coefficient **0**、ε_clip 0.2、4 mini-epochs、horizon 16、observation/value/advantage 全归一化。网络:MLP **[512, 512] → LSTM 1024**;critic [1024, 512]。

**DR**(每 720 仿真步施加一次):观测**和动作**都加 σ=0.01 高斯噪声;重力加性扰动 σ=0.3;物体和桌子的 scale/mass/friction 按 U[0.7, 1.3] 缩放;机器人 scale/damping/stiffness/friction/mass 同样 U[0.7, 1.3];**每时间步 5% 概率对物体施加物体质量 50× 的随机方向力**。

**成本**:**4096 envs,单张 NVIDIA A100 40 GB,~7k FPS,每任务 5–24 小时 wall-clock,约 0.6 B frames**(≈ 一年仿真经验)。一任务一 policy,共 7 个任务。

**形态**:**只有单手**。**16-DoF Allegro + 7-DoF KUKA LBR iiwa 14** —— 这是唯一一个**用真机械臂而非浮动腕**的。ZED 1 立体相机,桌面场景(静态箱子、平底锅、碗架)。**没有其他手被支持或演示过**;论文声称方法无形态特异性但零跨形态证据。GitHub issue #12("Can it only handle the right hand?")开着未答。非双手。

**G1 / Dex3 支持**:❌ 都不支持。

**代码/许可**:https://github.com/tylerlum/human2sim2robot —— **MIT**,"Copyright (c) 2025 Tyler Lum"。完整官方实现:real-to-sim、人类 demo 处理、PPO 训练、硬件部署。**Asset、全部任务的原始+处理后 demo 数据、预训练模型都发布**,但**通过 Google Form 换取下载 URL**(https://forms.gle/rUfrbuzKHW5BexcH6),由 `human2sim2robot/utils/download.py` 消费。不在 HF 上(issue #1 提了,仍开着)。

**失败模式 / 复现坑**:
- 论文自陈:只评测了一个形态;**只支持单物体**;需要高质量 pose tracker 和刚体仿真器,**articulated 或可变形物体需要不同的状态估计和仿真**;FoundationPose 在对称物体上有位姿歧义、在反光物体上深度有噪;一任务一 policy(5–24 h/次),无多任务通才;无双手/全身
- 实测失败:policy **利用仿真不准**(尤其桌面/静态物体摩擦建模不准);遮挡下位姿估计出错
- 最难任务 **plate-pivot-lift-rack**(薄盘从大号 Allegro 手里滑出);但实际**最低分是 plate-lift-rack(60%)**,plate-pivot-lift-rack 因为按 0/0.33/0.66/1 分段给部分分反而是 86.6%
- **GitHub #7 / #10(开)**:`fabrics-sim`(geometric fabric 控制器,动作空间的硬依赖)托管在 `https://gitlab.com/tylerlum/fabrics-sim.git`,**返回 "repository not found",不可公开访问**。这直接卡死控制栈的复现。#11 Allegro 自碰撞;#12 右手限制;#9/#8 管线流程和 `iiwa_allegro.yml` 配置

**指标**:**没有阈值化成功判据**。是**人工判定任务完成**,每任务每方法 10 次 rollout,部分任务分段给分(0/0.5/1 或 0/0.33/0.66/1)。真机结果(7 任务均值):Ours **92.4%**、Replay 25.7%、Object-Aware Replay 37.6%、BC(Diffusion,30 条合成 demo)24.3%。论文 headline 的 "+67% / +55% / +68%" 就是这三组均值的绝对百分点差。

**这意味着 CHORD 复现 H2S2R 时必然重新定义了评价方式 —— 而 CHORD 附录 G 只写了 DexMachina / ManipTrans / SPIDER 三个,完全没提 H2S2R 怎么复现的。**

# 第四部分:2026 年后续工作 —— 有没有人打败 CHORD

**结论:没有。目前没有任何公开工作在 AUC / SP-SR / MP-SR / MPPE 这四个指标上超过 CHORD。**

CHORD v2 是 2026-08-14,挑战 2026-09-21 才开、11-04 冻结。我扫了 arXiv cs.RO 近一年 "dexterous + human demonstration" 的全部条目,没有任何一篇报这四个指标。

值得盯的几篇:

**Weave**(arXiv 2609.16683,2026-09-15,https://xiaohu-art.github.io/Weave/)—— **离 Track 2 形态最近**。Unitree G1 **29 body DoF + 两只 Inspire 手 12 finger DoF**,统一 policy,contact-aware retargeting + approach-motion completion。PPO + **真 asymmetric actor-critic**(critic 多拿 base linear velocity 和 tracked-body pose),SimBaV2 网络 + Muon 优化二维权重矩阵 / AdamW 优化其余,**200 Hz 物理 / 50 Hz 控制**。观测含 **BPS-SDF 物体几何描述子 + 指尖到表面向量 + 二值接触 flag**;reward 含 **hand-opposition reward**(鼓励拇指和对指落在物体表面两侧)。终止:pelvis 位置误差 > 0.25 m、物体位置误差 > 0.30 m、pelvis/物体 projected-gravity 误差 > 0.8/0.3、踝或腕垂直跟踪误差 > 0.25 m、**期望接触连续缺失 10 步**。9 个物体、7,869 条训练参考(19.56 h)/ 1,605 条测试(3.67 h);训练集 SR 从 10k iter 的 78.0% 升到 100k 的 **92.5%**,未见序列 **65.0%**;物体旋转误差 11.17° → 7.18°,位置 5.17 → 4.27 cm。统一 policy 95.3% vs 各物体专家 91.5%。释放 ~9,000 条 rollout / ~23 h。
**它没有和 CHORD 比,指标体系不同(SR + progress rate + 分项 tracking error,clip-balanced 平均)。** 用 Inspire 不是 Dex3。但 "接触缺失 10 步终止" 和 "hand-opposition reward" 两个设计可以直接借。

**ConTrack**(arXiv 2606.03177 v2,https://www.lyt0112.com/projects/ConTrack)—— 把物体跟踪当**约束**,用 dual-variable 在线分配 task/style 权衡;配 **adaptive mid-trajectory reset library**:从 policy **实际可达**的仿真状态重启,而不是直接把仿真器 set 到参考帧("In hand–object interaction, such resets can be physically inconsistent because contact configurations may not be realizable under the simulator dynamics")。PPO 用三路 advantage(task / style / penalty)混合。**明确比了 ManipTrans / DexMachina / SPIDER 并全胜**。单张 RTX 4090,5000 次 PPO update/clip,1.9–2.9 h,约 5.6–6.4×10⁸ simulator steps;DexterHand Ring 用 100,000 updates 可达 94% SR。自己的指标:pose-break 阈值 **0.10 m / 1.00 rad**,SR = 跑到 `τ = T−1` 的比例,progress = 归一化终止位置。数据集 GRAB / ARCTIC / DexterHand;真机 xArm7 + xHand 双臂。接触标注用 **5 mm** 邻近阈值、15 个手部 segment。
**"reset 到 policy 可达状态而不是参考状态" 对 CHORD 的随机帧 reset 是个直接改进方向。**

其他相关但不构成威胁:
- **REGRIND**(2607.11874,https://yunhaifeng.com/REGRIND)—— 极简 retargeting-guided 残差 RL,单条 demo,object-centric keypoint 跟踪,零样本上真机(剪刀、螺丝刀),两种多指手
- **TopoRetarget**(2606.16272,https://toporetarget2026.github.io/TopoRetarget/)—— interaction-preserving retargeting,稀疏交互图 + 距离加权 Laplacian 形变,ContactPose 上接触精度最好,Pen-Spin 训练成功率 **+40.6 个点**,零样本上 Wuji Hand
- **ReForce**(2608.15560)—— force-aware retargeting,在 kinematic retarget 结果上预测残差达到期望力,通用力跟踪器训在大规模仿真交互上
- **DexMan**(2510.08475,https://embodiedai-ntu.github.io/dexman/)—— 第三人称视频 → 人形机器人双手,无需标定/深度/扫描资产;TACO 上 ADD-S +0.08、VSD +0.12,OakInk-v2 上 RL 成功率比前作 **+19%**
- **DexMani**(2608.00554)、**AdvDex**(2608.14028)、**V2P-Manip**(2606.16436)、**EgoAERO**(2606.08057)、**DexVerse**(2607.08751)、**Play2Perfect**(2606.26428)—— 与这四个指标无交集
- **Dexterous Manipulation Transfer via Progressive Kinematic-Dynamic Alignment**(2511.10987,AAAI 2026)—— 平均转移成功率 73%,自己的指标

# 第六部分:对打 Track 2 的判断

**1. 指标结构决定优化顺序。**
- SP-SR(0.1 m / 0.5 rad)最松,是"别把物体搞丢"的及格线
- MP-SR(30° / 3 cm / 8 cm MPJPE / 6 cm 指尖,四条全中,双手任一失败即整条失败)最严,且**唯一惩罚"抛弃人手参考"**
- AUC 和 MPPE 都是 cm 级连续量,AUC 在 1–9 cm 上积分,MPPE(若猜测成立)约 1.17 cm/度

所以"为压物体误差把 imitation reward 砍掉"会在 MP-SR 上付代价,"死守 retarget 参考"又会在 AUC/MPPE 上付代价。CHORD 的解法就是 wrench-space reward —— 允许手姿偏离人,只要对物体的机械作用等价。这是它同时拿下六项的原因,也是这条赛道的核心 insight。

**2. SPIDER 那一行是警示。** SP-SR 0.911 / JPE 41.35° —— 只优化物体轨迹能刷高 SP-SR 但手完全跑飞。四个指标必须联合监控,不要单点优化。

**3. 可直接抄的工程细节**(全在 Apache-2.0 的公开 repo 里):
- VOC curriculum 必须等 contact wrench reward 收敛后再衰减
- reset 时手指按 `U[0, 0.7]` 部分张开 + VOC 20 步 warm-up;whole-body 用 shoulder yaw offset 0.5 把手臂拉离物体
- action EMA 0.3,residual scale 0.05 m / 0.15 rad / 0.15 rad
- whole-body 三阶段(无碰撞预热 → 接触 grounding → 全长 finetune)
- Tier 2/3 噪声档位直接参考 CHORD Appendix A.1 的六档表
- 高噪声时切 `force_closure` reward —— 但记得同时把三个 contact 项**和它们在 curriculum 里的 `rewards_*` 参数**一起清零

**4. 起步可借的外部资产**:DexMachina(MIT)的 `envs/hand_cfgs/dex3.py` + `assets/dex3_hand/` 已有 Dex3 的 6-DoF 浮动腕配置和 retarget config,可以拿来做 baseline 对拍。避开 ManipTrans(GPL)和 SPIDER(NC)作为代码基座。

**5. 还没被吃掉的增量**:privileged critic(CHORD/DexMachina/ManipTrans 都没有,Weave 和 H2S2R 有);policy-reachable reset library(ConTrack);接触缺失连续 N 步终止(Weave);BPS-SDF 几何条件(Weave/ManipTrans 有,CHORD 没有)。

**6. 最重要的一件事**:9/21 数据一发,**第一时间跑官方 `eval_robotic_grounding.py` 并逐行读它的 metric 实现**,确认(a) MPPE 的 keypoint 定义和臂长、(b) AUC 的 part 聚合顺序、(c) Tier 2/3 对照的是脏 reference 还是干净 GT。这三件事没锁死之前的调参可能全白调。
