## 1. 做什么

先 `scripts/dev/remote` 同步到 ml40，核对 `.v2d-source-commit` 是第 2 版的提交。
ml40（GPU，用前等卡空，挂 fc_8c778f9，`V2D_GPU=1`）：`stages/evaluate/t12ctl_chain.sh` 对四集成功集的原参考（`runs/motion/tier2`）各跑
`diag_rollout.py --worlds 1024 --palms --bodies --parquet …` → `diag2_sync.py` → `fall_mechanism.py --before <该集第一次接触帧>`：
- 用 ep4-sd checkpoint（`smoke-t2-ep4-w2048-cap4m-r3a-sd-mf4090/policy_409600`，support False）：ep21（`2026-04-29_11-53-57_tall_bar_stool_pull_08`，t_c 95）、
  ep15（`2026-05-06_11-06-15_wet_floor_sign_pick_place_ground_08`，126）、ep0（`2026-06-04_14-16-23_tall_bar_stool_tip_up_04`，203，走得慢的成功集，v·|ω| 1.04）。
- 用 ep25-sd checkpoint（`smoke-t2-ep25-w2048-cap4m-r3a-sd-mf4090/policy_409600`，support True）：ep16（`2026-03-12_15-06-36_spray_bottle_left_desk_ground_02`，t_c 109）；
  以及 ep4 原参考（`2026-04-24_11-40-52_baseball_bat_rotate_05`，133）做“与 checkpoint 无关”的核对：要复现 ep4-sd 的摔倒帧 88/88/89（分位相差 ≤ 2 帧）。
ep21、ep16、ep15 是接触前 v·|ω| 最猛的三集成功集。每份约 3 分钟，共约 20 分钟。

## 2. 判据（登记）

- C0：每集 G0 过（照 t12fall 门槛）、同步闸过、评测 JSON 的 parquet 核对过；ep25-sd 配 ep4 参考复现 88/88/89（±2 帧），不复现就整轮不判（前提不成立）。不过 G0 等的那一集不判。
- 计数：“接触前摔倒”= 摔倒帧早于该集第一次接触帧，且摔时物体离起点 < 0.05 m（`FALL_BEFORE_STILL`，排除腿先碰到物体再摔，同 t12replay R1(a)）；原始比例（`FALL_BEFORE`）并列报。
- 各世界只差随机的 0–2 步执行延迟（ep4 是 88/88/89），一集的结果基本是“摔 / 不摔”二选一；所以判据按集数算，50% / 20% 只用来定每一集算哪边。
- C1（回放会摔不是失败集特有的）：过了 C0 的 4 集成功集里，≥ 2 集“接触前摔倒”的世界 ≥ 50%。成立就把 R1 的读法降级：零残差回放摔不摔不能代表训练能不能拿下；
  t12ref 那类“先用回放筛参考”的做法作废，改参考的效果只能靠训练量。
- C2（回放会摔是失败集特有的）：过了 C0 的成功集全部“接触前摔倒”≤ 20%。成立就保留 R1：ep4 的走路段有现有统计量抓不到的东西，下一步查看器逐帧看（要用户看）或另找量。
- 介于两者之间记“混合”，逐集报，不下结论。
- 不按榜上分数挑东西；这一轮不提交（`agent-doc/strategy-2026-10-19.md` 第 1 节）。

## 3. 风险

- 成功集的参考换了物体，物体在仿真里被碰的方式不同；回放的动作只跟参考有关，但摔不摔会受物体影响（接触后）。所以只看接触前。
- checkpoint 配置里其余按集设定的值（如 reference.num_frames）不跟着换；残差为 0 时它们不进动作，只可能进观测，影响不到回放。
