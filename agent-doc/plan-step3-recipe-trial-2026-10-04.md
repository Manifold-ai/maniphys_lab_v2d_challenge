用户 10/4：“先做第 3 步：用改过的配方在约 5 条序列上小规模试，过了登记的判据再铺开到 30 条。然后 Tier 2 的降噪改进可以和第 3 步并行，
Tier 2 要用它自己的数据另行验证，还是需要先计划的。”工作顺序是用户 10/1 定的：导出与提交流程、诊断、配方试验。第 2 步诊断的对照没过，
结论不成立；本计划挑序列只用评测与训练记录里照实描述的数，不用诊断的结论。Tier 2 降噪另写计划（`agent-doc/plan-tier2-denoise-2026-10-04.md`）。
时间一律 UTC-6。

## 1. 事实

**配方**（FlashCHORD v0.4.0，`configs/experiment/g1_recon_body_flash_sac.yaml`）：3.5 亿环境步、2048 个世界、逐帧回放；课程 9 段
（`configs/curriculum/recon_body_flash_sac.yaml`），VOC（给物体的虚拟辅助力）1 → 0.75 → 0.5 → 0.25 → 0.1 → 0.05，第 7 段（2.1 亿步）起为 0，
最后两段混入 25%、50% 从第 0 帧直接开始的回合。每一段课程自带一套奖励权重（同一个锚点，12 项与 `objective` 配置相同）。

**奖励里关于物体的只有位置一项。** 奖励 12 项（`objectives/recon_body.py:26–38`）：终止、动作两项、关节限位、骨盆位置与朝向、全身关节位置（权重 5）、
物体位置（权重 1）、进度、手掌位置与朝向、力闭合（权重 5）。**没有物体朝向项。** 物体位置项是 `exp(-|e|²/σ²)`（`recon_body.py:276–278`），
σ = `object_position_std` = 0.2 m（`configs/objective/recon_body.yaml:17`）：误差 1 cm、3 cm、5 cm 时分别是 0.998、0.978、0.94，
在 MP-SR 的 3 cm 门槛附近几乎没有区分。物体朝向只受终止约束：`configs/termination/recon_body.yaml` 的 `object_orientation_threshold: 1.50`（86°），
位置 0.10 m，重置后 50 步内不判。

**排行榜的四个指标与终止阈值无关，chord_sr 有关。** MP-SR 要求每个世界按帧平均的位置误差 < 3 cm 且朝向 < 30°，SP-SR 是 ≤ 0.1 m 且 ≤ 0.5 rad，
都是评测器代码里的常数（`evaluation/metrics.py:21–24, 296–349`，见 `agent-doc/experiments/2026-09-30-batch1b-failure-analysis.md`）；ADD-AUC、MPPE 同样不读配置。
评测时终止阈值一律改成 1e6，失败的世界照样走完（`evaluation/harness.py:173–207`）；`chord_sr` 在改之前从 checkpoint 自带的终止配置里取阈值（`harness.py:141–170`），
所以改了终止阈值之后，chord_sr 在变体与基线之间不可比，评测的 rollout 本身不受影响。

**评测器按 checkpoint 自带的配置重建环境**（`harness.py:331–355`：`instantiate_typed(cfg.env, RLEnvConfig)`；`harness.py:384–393` 按 checkpoint 记的课程段设奖励）。
只改已有字段的取值时，官方 8c778f9 评测器照样能读；加一个新的奖励项要改代码，配置里会多出评测器不认识的字段，违反“评测与导出用 8c778f9”的决定
（`agent-doc/decision-organizer-q1-q3-2026-10-01.md`）。**本计划只改取值。** 配置里 `env.objective`、`env.termination` 是对顶层 `objective`、`termination` 的引用
（`configs/env/rl.yaml:13, 16`），顶层覆盖会一起带过去。

**两档“差一点”的 episode 多，卡在哪一项看得出来**（4096 世界评测、最终 checkpoint；平均物体位置误差 / 朝向误差 → MP-SR；
`results/day2/eval_<run>_s349999104.txt`、`results/ml40/day2/eval_<run>_s349999104.txt`）：

- Tier 1（mf4090，对照干净参考）：ep6 3.3 cm / 12.7° → 0.562；ep18 4.1 / 11.1 → 0.152；ep27 5.6 / 12.7 → 0.321；ep29 3.5 / 5.8 → 0.174（这四条卡在位置）；
  ep20 3.8 / 35.5 → 0.016（卡在朝向）。ml40 上的 ep15 4.5 / 30.4、ep17 8.9 / 42.0 也卡在朝向（第 1 批失败分析，jev 10 / 10）。
- Tier 2（ml40，对照 v5.4 参考，即策略的输入）：ep8 3.3 / 8.2 → 0.021；ep12 4.1 / 9.0 → 0.001（卡在位置）；ep20 4.0 / 35.7 → 0；ep24 3.7 / 30.8 → 0；
  ep26 2.4 / 32.3 → 0.006（卡在朝向）。

**训练记录指向同两处。** Tier 2 自己的训练记录（`results/ml40/t2/wandb_by_stage_trial_candidates.txt`，按课程段，对照 v5.4）：VOC 撤掉的过程中，物体朝向误差
ep20 0.12 → 0.61 rad，ep24 0.09 → 0.51，ep26 0.32 → 0.58；物体位置误差 ep12、ep24 在 VOC 全开时已是 3.5、3.8 cm，最后一段 3.6、4.1 cm，
ep8 从 1.8 cm 涨到 3.2 cm。Tier 1 的 ep15、ep17 有同样的朝向漂移（失败分析）。

**同配方只换种子的波动只量过一次，而且在地板上。** ep20 在 mf4090 上有一对同配方、只换种子的 run（实时回放、400 万 buffer，s42 与 s43）：
MP-SR 0 与 0.0002，ADD-AUC 0.421 与 0.411，chord_sr 0.138 与 0.115，两条都失败，结果接近。换配置差别就大：同样实时回放，ml40 上 1000 万 buffer 的那条 MP-SR 0.887；
逐帧回放下 mf4090 400 万 buffer 0.016、ml40 1000 万 buffer 0.0005。中间段（MP-SR 0.1–0.6）换种子的波动没有量过，所以试验必须自带重复种子。

**评测器版本。** 10 条基线（seed 42）当时用 v0.4.0 的评测器评；新 run 由评测链用 8c778f9 副本评。兼容性验证里同一个 checkpoint（t1-ep6）两版评测器的 4096 世界结果
ADD-AUC 差 0.0014、MP-SR 0.562 对 0.570（`agent-doc/experiments/2026-10-02-box6-eval-runtime.md` P4）。为了同口径，基线也用 8c778f9 重评（第 7 节第 3 步）。

**算力与磁盘。** 一条正式训练约 2 小时（10/2 两条重训 1:57、2:00），冒烟、冒烟检查与 4096 世界评测再加约 10–15 分钟。mf4090 现在可用 8.7 GB，
一条 run 留 1 份 state 约 0.33 GB；ml40 可用约 1.8 TB。

**净室。** Tier 2 的决定只用 Tier 2 的数据：试验序列按 Tier 2 自己的评测与训练记录挑，判据对照 v5.4 参考，变体的取值来自官方指标的门槛（3 cm、30°），不来自任何 Tier 1 的数。
Tier 1 的结果只用于 Tier 1。

## 2. 变体（只改取值，不改代码）

**变体 A（“对齐 MP-SR”）**，两处改动，其余与基线完全相同（buffer、课程、步数、训练副本、种子的写法）：

| 字段 | 基线 | 变体 A | 理由 |
|---|---|---|---|
| `objective.object_position_std` | 0.2 m | 0.05 m | 误差 1 / 3 / 5 cm 时奖励 0.96 / 0.70 / 0.37，3 cm 附近对误差的斜率是原来的约 11 倍；10 cm 时 0.02，由 10 cm 的位置终止兜住 |
| `termination.object_orientation_threshold` | 1.5 rad | 0.6 rad（34°） | 奖励里没有朝向项，只能经终止施压；取略宽于 MP-SR 30° 的值，冻结期 50 步照旧；评测时终止阈值本来就改成 1e6，评测的 rollout 不受影响 |

改的是 σ 不是权重：权重写在 9 段课程里，各段要一起改；σ 只在 `objective` 里。朝向终止是逐帧判的，MP-SR 看的是按帧平均，34° 的逐帧上限比 MP-SR 的要求更严，方向一致。

为什么只试一个变体：预算有限，两处改动检验的是同一个假设，“配方没有要求 MP-SR 量的东西”。A 过了再按需拆开做消融；A 不过就带着结果重新分析，
不在同一批数据上反复调参。

## 3. 试验设计

| 档位 | 机器（buffer） | 试验序列（基线 seed 42 已有） | 新跑的 run（每条序列 3 条） |
|---|---|---|---|
| Tier 1 | mf4090（400 万） | ep6、ep18、ep20、ep27、ep29（基线 `t1-ep<N>-w2048-cap4m-mf4090`，都是现在导出的 run） | 变体 A seed 42、变体 A seed 43、基线 seed 43 |
| Tier 2 | ml40（1000 万） | ep8、ep12、ep20、ep24、ep26（基线 `t2-ep<N>-w2048-cap10m-ml40`，都是现在导出的 run） | 同上 |

- 每档 15 条新 run，两台各跑一档、并行，约 15 × 2.2 小时 ≈ 33 小时。顺序：先 5 条变体 A seed 42，再 5 条基线 seed 43，最后 5 条变体 A seed 43（第 4 节的中途检查用前 5 条）。
- 命名：`t<档>-ep<N>-w2048-cap<4m|10m>-r3a-<机器>`（变体 A、seed 42）、`…-r3a-s43-<机器>`、`…-s43-<机器>`（基线配方、seed 43），与已有 run 都不重名。
- 全部用带防护的训练副本（链的环境给 `V2D_ALLOW_FC_SRC=1 V2D_FC_SRC=<机器>/fc_src/v040_p185_nfg`）。这 10 条序列都不在方盒的三条（ep1、ep7、ep28）里，#185 不起作用；
  没有事件时防护不改变训练：终止 kernel 与上游逐位相同（K1，6400 次世界评估），学习器侧只替换非有限值（K3）。基线 seed 42 是 9/29–10/1 用 v0.4.0 原副本训的，
  这是四组里唯一用旧副本的一组。
- 队列行照 ep7 重训的写法（`V2D_WANDB_UPLOAD_CKPT=0`、`V2D_MAX_RETRY=0`、`V2D_GPU_APPS=1`），`V2D_WANDB_TAG=r3`、`V2D_KEEP_STATES=1`；seed 43 的行末加
  `reset.seed=43 training.seed=43`（9/30 的 s43 run 用过同样写法）；变体 A 的行末加 `objective.object_position_std=0.05 termination.object_orientation_threshold=0.6`。
- 每条先冒烟（链照常），正式训练完由评测链用 fc_8c778f9 副本评最终 checkpoint（4096 世界）。

## 4. 判据（执行前登记，每档分开判）

记 MP_A(e)、MP_B(e) 为 episode e 上变体 A、基线两个种子（42、43）的 4096 世界 MP-SR 的平均，全部用 8c778f9 评测器的数；ADD-AUC、SP-SR、MPPE 同理。

| 编号 | 判据 |
|---|---|
| S1 主判据 | 5 条的平均 MP_A − 平均 MP_B ≥ 0.15 |
| S2 一致 | MP_A(e) > MP_B(e) 的 episode 至少 3 条 |
| S3 不大退 | 没有一条 MP_A(e) < MP_B(e) − 0.20 |
| S4 不伤其他指标 | 平均 ADD-AUC_A ≥ 平均 ADD-AUC_B − 0.02；平均 SP-SR_A ≥ 平均 SP-SR_B − 0.10；平均 MPPE_A ≤ 平均 MPPE_B + 0.5 cm |
| S5 训练健康 | 15 条都跑完（有 DONE、最终 policy 有限、没有 `NONFINITE_GUARD_STOP`）；有没跑完的照实记，S1–S4 按跑完的算并注明 |

S1–S4 都过，这一档判“变体 A 通过”，进第 5 节；任一不过判“不通过”，照实报告，不在同一批数据上换参数重试（要试别的变体另写计划）。

**中途检查（只许判停，不许判过）**：一档的 5 条变体 A seed 42 都评完后，若 5 条 MP_A,42(e) − MP_B,42(e) 的平均 ≤ 0，并且没有一条 ≥ +0.10，
这一档判“不通过（中途）”，停掉剩下的 run，腾出 GPU。否则跑完，不看中途数做别的决定。

只报、不作判据：chord_sr（与终止阈值有关，不可比）、按课程段的训练误差与终止率、防护事件、基线两个种子之间的差（第一次量中间段的重训波动）。

## 5. 通过之后（铺开）

- **Tier 1**：其余 25 条用变体 A、seed 42 重训。mf4090 试验后约剩 3.7 GB，不够再跑十几条：要么旧 run 的 state 归档到 HF 后删本地（沿用 `tools/hf_archive_run.sh`，
  先核 HF 上的 sha256；删之前问用户），要么多分给 ml40（1000 万 buffer，与试验的 400 万不同，靠下面“每条交哪一个”兜底）。
- **Tier 2**：取决于降噪计划。新的 Tier 2 参考若会被采用，铺开时直接在新参考上训，免得 30 条训两遍；否则在 v5.4 上训。
- **每条 episode 交哪一个**，要用户定（与 10/2 “按规则、不按分数挑”的约定不同）：甲，全部换成变体 A；乙，每条在已评完的 run 之间按 4096 世界 MP-SR 取高者，
  相同取 ADD-AUC 高者。我们建议乙：4096 个世界的 MP-SR 抽样误差约 ±0.008，按它挑带来的乐观偏差很小；Tier 2 按对照 v5.4 的评测挑，这与排行榜对照的干净真值不是一回事。
- 之后照提交流程：改导出规则与测试、导出、拉回、打包、上传器只跑 `--dry-run`；真提交等用户确认。

## 6. 风险

- 收紧位置核可能让训练前期更难（误差大时这一项几乎为 0）；朝向终止可能让 VOC 撤掉后终止变多、进度下降。按课程段看训练记录，只报。
- Tier 2 的判据对照 v5.4：跟得更紧不等于排行榜更高。v5.4 自身残留的朝向误差也可能让朝向终止在物理上做不到的地方触发（例如物体静置、参考却在转）；
  按课程段看物体终止率，只报。
- 两个种子量不准小的提升，S1 定在 0.15 是为了只认大的提升。试验序列是按基线 seed 42 的结果挑的“差一点”，seed 42 的数可能偏，所以基线也补 seed 43。
- 评测兼容：只改取值，但正式开跑前要实测官方 8c778f9 评测器能读变体 A 的 checkpoint（第 7 节闸 G1）。
- mf4090 磁盘：试验 15 条约 5 GB，现有 8.7 GB 够（链在 mf4090 上要求可用 ≥ 1.2 GB 才起下一条）。
- 档位隔离：见第 1 节最后一条。两档的试验与判定分开记录；Tier 2 的判定脚本开头调 `forbid_tier1()`。
