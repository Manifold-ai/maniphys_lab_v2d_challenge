### 执行偏差：mf4090 冒烟的显存上限（16:58 登记，早于 B 的任何正式训练结果）

- 现象：mf4090 训练链 16:53 结束，完成 0、失败 0、跳过 3。三条冒烟都跑完（B-rt 36,001,792 步，另两条 4,096,000 步），
  日志里没有 RESOURCE_EXHAUSTED / base limit / out of memory。链判冒烟不过的唯一理由是整卡显存峰值 23843 / 23845 / 23855 MiB
  超过 23000（`results/day2/chainlog_day2_train_mf4090.txt`）。
- 23000 是开链命令的第 4 个参数，沿用 Day 1 的 mf4090 冒烟（100 万 buffer，峰值 11.6 GB），没有写进计划。计划 B 节登记的显存判据是
  日志里出现 XLA 的 RESOURCE_EXHAUSTED / base limit 或 Warp 的 out of memory。开链参数与登记的判据不一致，是开链时的疏忽。
- 显存曲线：B-rt 开跑约 2 分钟升到 23843 MiB，此后 424 个采样里 366 个是 23843、2 个是 23841（其余是起停），跨过 buffer 填满、
  3 次 checkpoint 保存和第一个 curriculum 阶段都没有变。整卡 24564 MiB。整卡读数比事实 8 的推算（XLA 部分约 18 GB）高，
  训练关了预分配，XLA 按需扩池，整卡读数反映池子大小，不能单独说明缺显存；缺不缺看 XLA 报不报 RESOURCE_EXHAUSTED，也就是登记的判据。
- 处理：上限改成整卡总量 24564 MiB，等于不再按峰值判、只按登记的 OOM 字样判。三条冒烟按它重核全过
  （`results/day2/smokecheck_cardtotal_*.txt`）。用同一来历 67f1d86 重开 mf4090 的训练链与评测链（日志名加 `_r2`）：冒烟已 DONE 不重训，
  接着做 256 世界 rollout、不动基线、帧数核对，再跑三条正式训练。
- 这是看到 23843 之后做的改动，单独标注。正式训练中途 OOM 仍按计划记“B 无结果”，不自动降档。
