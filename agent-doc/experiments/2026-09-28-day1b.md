## 事先登记（开训与诊断之前；提交时间即登记时间）

### A. 满配 snack_box 对照：`ctrl-snackbox-w2048-cap10m-ml40`

- 设置：官方 G1 配方，只给官方样例 parquet（sha256 `04f55c50…`）；2048 世界、349,999,104 步、默认 1000 万 buffer，无任何覆盖；seed 42；
  `V2D_MAX_RETRY=0`（续训不恢复 replay，失败即停、从 0 重来；若人工续训，该 run 标为偏离，不通过也不作“配方/环境有问题”的证据）。
  之前先跑冒烟 `smoke-snackbox-w2048-cap10m-ml40`（409.6 万步，W&B `v2d-selftest`），判据见计划 A1；冒烟不过不开正式训练。
- 评测：最终 `policy_349999104`，ml40，4096 世界，官方默认评测配置。
- 通过：`chord_sr > 0` 且 `maniptrans_sr > 0` 且 ADD-AUC > 不动基线。
- 不动基线：用评测器自己的顶点（rollout 的 `object_vertices_o`）算的“物体保持第 0 帧参考位姿”的 ADD-AUC；0.5662 是 trimesh 顶点算的，
  判定前用 B 里 snack rollout 的顶点复算，差超过 0.002 就用复算值（`verdict.py --bar-check-diag results/day1/diag_ctrl-snackbox-w2048-cap1m-mf4090.txt`）。
  snack 静止的前 440 帧里约 317 帧是上游加的前缀，这个门槛主要考“前缀期间别碰盒子”。
- 边缘：`chord_sr` 或 `maniptrans_sr` 的“> 0”只靠 ≤ 3 个世界，或 ADD-AUC 落在门槛 ±0.01 以内 → 标“边缘”，不走 SOP 的任何因果分支，
  下一步按诊断证据定，或补一个种子。混合结果（例如 ADD-AUC 过而 chord_sr = 0）按判据就是不通过，写清哪一项没过。
- 次要（只描述）：逐段 ADD-AUC 与逐段不动基线；与 100 万版本之差；成功世界计数。
- 结论只写到：通过 →“这个种子在官方样例上胜过不动；ep20 的失败特定于 ep20，原因在我们的管线、这条序列的任务或两条序列的其他差异之中”；
  不通过 →“这个种子在官方样例上没胜过不动”，原因可能在配方本身、以静止段为主的门槛或环境。

### B. 逐帧诊断：ep20 满配（`959c729e…`，主）、ep20 100 万（`6545b652…`）、snack 100 万（`072eab94…`）

- 同一张 RTX 4090、4096 世界，snack 100 万排第一：先跑原样的 `fc_eval.sh`，再跑 `diag_rollout.py`（runpy 运行未改动的 `evaluate_policy.py`，只多包一层存下 rollout）。
  正式之前先用 9/25 的冒烟 policy 以 256 世界端到端试跑一遍（不计入结果）。
- 闸（任何一道不过：该 policy 只报数字、不分类、不解读；其余 policy 照跑）：G0 形状；G1 同卡包装前后逐位相同（不同则 chord_sr 的 |z| < 3 且 |ΔADD-AUC| < 0.005，注明）；
  G2 重算全程 ADD-AUC 等于评测 JSON；G3 按位姿算的朝向误差与评测器的最大差 < 0.1°；G4 参考的已知答案
  （ep20：209 / 420 / 269；snack：446 / 704 / 504，来自 `static_baseline_*.txt`）；G5 逐世界成功率重算一致；
  **G6 几何自检**：任务原生判据下成功的每个世界 w，第 F 帧物体离自身初始朝向 ≥ 参考该帧离初始朝向 − 1.5 rad − e₀(w) − 0.1°
  （e₀ 为该世界第 0 帧的朝向误差；三角不等式，逐世界判；ep20 取 F = 359，snack 取 F = 601；没有成功世界时不适用）。
- 问题：Q0 ADD-AUC 分段（ep20 0–208 / 209–420 / 421–552；snack 0–445 / 446–704 / 705–799）与逐段不动基线、逐段贡献；
  Q1 朝向误差随时间与逐世界首次越线；Q2 绕参考主轴的带符号转动（净转动比、209 帧到末帧净转、段内峰值；分类：净转过半 / 转过但没保持或没跟上 /
  基本没转 / 其他；达到第 420 帧不越门槛所需比值的世界比例；跳变计数）；Q3 手（只报数：palm 误差两手取大、参考手到参考物体网格的距离、参考接触标记）；
  Q4 失败世界首次越线的时间与原因。诊断数字不进判据表。
- 结果 → 下一步（数值条件，`diag_triggers.py` 判定；主 = ep20 满配，对照 = snack 100 万；任何报告的闸没过就不判定）：
  T1 非操作段（第 1、3 段）占全程 ADD-AUC 差 ≥ 50% → 查接近与抓取、reset 与 VOC；对照也 ≥ 50% → 归到配方层。
  T2 中位净转动比 < 第 420 帧不越门槛所需比值（约 72%）→ 做回放速度对照（1.67 倍速 vs 真实时长）。
  T3 操作段 palm 误差中位 ≥ 7.5 cm → 查策略。
  T4 参考接触帧上 palm 到物体距离中位（各接触手取最小）比对照大 ≥ 2 cm → 查重定向管线。都没触发 → 如实报告。

### 不下的结论

- 单种子：不说“配方能/不能训出 snack_box”。
- 1000 万与 100 万之差不单独归因于 buffer（同时换了 GPU 与机器）。
- 误差集中在 209–420 是任何滞后策略（包括完全不动）的默认形状，要看 Q0 的逐段对比。
- 诊断数字不外推到 Tier 2/3、其他序列或排行榜，也不回头改 Day 1 的判定。
- snack 的采集帧率未知：若是 30 fps，它与 ep20 同为 1.67 倍速播放；若是 50 fps 则为真实速度。所以不说两条序列播放速度相同。
