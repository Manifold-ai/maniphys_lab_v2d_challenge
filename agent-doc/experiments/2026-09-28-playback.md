## 官方评测的回放速度（09-28 14:40 MDT 查证；撤回“很可能是 1.67 倍速”）

证据：`results/playback/official_playback_sources.txt`（`stages/policy/playback_official_sources.sh`，直接读 GitHub 上的赛事页面源码与三个发布版本）、
`results/playback/upstream_playback_facts.txt`。

- 赛事页面（main 分支 `docs/v2d_challenge/index.html`）：Track 2 只写了 “Embodiment and simulator are fixed and provided: G1 + Dex3”、
  “Teams will submit recorded evaluations of their trained policies using the eval_robotic_grounding.py script provided to produce the artifact for submission”、
  按 “the clean multi-view captioned object trajectory” 计分。页面源码里 playback / fps / frame rate / Hz / real time / speed 出现 0 次；
  `eval_robotic_grounding.py` 还没发布。未发布的赛规草稿（分支 `codex/v2d-challenge-rules-feedback` 的 `rules.html`）也没写回放速度。
- 代码，三个发布版本：
  - release/0.2.0（赛事页面链接的 starter toolkit，Isaac Lab）：全身 tracking 不重采样（`target_fps` 默认 None，“uses data as-is”，命令里没用到），
    每个 0.02 s 的环境步帧号加 1 → 30 fps 的参考按 1.67 倍速播放。
  - release/0.3.0 与 v0.4.0 的 Isaac Lab：按 parquet 的 fps 重采样到 1 / (env_step_dt × motion_speed)，G1 的 motion_speed 默认 1.0
    → fps 标对时按真实时长播放。
  - v0.4.0 的 FlashCHORD G1 配方：逐帧回放 → 1.67 倍速（计划事实 2、15）。
- 结论：官方文档没有定下评测的回放速度；当前版本里两条官方训练路径不一致（Isaac Lab 真实时长，FlashCHORD 逐帧 1.67 倍速）。
  计划事实 15 的推论只对 FlashCHORD 成立，撤回。以下只是解读、不是官方说法：Isaac Lab 这条从 0.2.0 到 0.3.0 改成了真实时长；
  页面说“simulator is fixed and provided”，而发布时提供的是 Isaac Lab。若评测走 Isaac Lab，连仿真器也和我们训练用的 FlashCHORD（Newton）不同。
- jev（`results/playback/jev_claims_official_playback_run3.txt`，对照正常）：页面没写 0.97、0.2.0 原样逐帧 0.72、0.3.0 起重采样 0.92、
  FlashCHORD 逐帧 0.81、官方来源定不下且两条路径不一致 0.72、不支持“很可能 1.67 倍速” 0.79。0.2.0 那条前两次是 0.26 / 0.63：
  证据里混了三个版本的行、也没有“确实没有重采样”的证据，改为逐行标版本并补上计数后重测。
