## 1. 判据（算结果之前写定）

- **D1 事实表。** 每个换入的集列旧 run 与新 run：4096 世界对各自参考的 SP-SR、MP-SR、MPPE、ADD-AUC，导出那一局对各自参考的 SP、MP 成功与 MPPE。数从已有记录读；没有记录才算，并注明。
- **D2 传递。** 用已交的整版清单校准“对自己参考 → 榜”：数该清单导出那一局对自己参考的 SP 成功集数，与榜上 SP-SR 集数比。只有第 0 帧对齐的提交才可比（未对齐的提交世界坐标系不同，不能当校准）；可比的提交少于 2 次时，传递记“未校准”，D4 只给区间不给点估计。
- **D3 榜单规则。** 从记录确认两条：(a) Kaggle 每个榜显示各队最好的一次；(b) 同分的新提交会不会把我们的时间戳后移（Kaggle 同分按先提交者在前）。(a) 成立时，分数变差的重交不降名次；(b) 成立时，分数相同的重交在同分榜上会掉名次。
- **D4 逐榜判定。** 新清单榜上 SP 集数的区间：下界 = 10 − 换出的旧 run 里导出那一局对自己参考 SP 成功的集数（假设它们在榜上全成功、而换入的全失败）；上界 = 10 + 换入的新 run 里导出那一局对自己参考 SP 成功的集数（假设换出的在榜上本来都失败、换入的在榜上全成功）。下界里“换出的旧 run 在榜上成功”只按它对自己参考成功来数，对自己参考失败却碰巧对真值成功的情形不计。
  - SP-SR：现在 12 集的两队都比我们新提交早，Kaggle 同分规则下要 ≥ 13 集才前进一名。下界 ≥ 13 记“可能前进（较有把握）”；上界 ≥ 13 而下界 < 13 记“有可能”；上界 < 13 记“不大可能”。
  - MP-SR：同理，≥ 4 集才前进；= 3 集时按 D3(b) 判会不会掉名。
  - AUC、MPPE：榜上是 30 集平均，对自己参考的 AUC、MPPE 到榜上的传递没有校准（策略第 0 节第 7 条：自参考 MPPE 每集 2–9 cm，榜上 50–55 cm，差在重建与真值之间）。只按机制判：前进一名所需的 30 集合计变化量，对比换入的集在自参考上的变化量；后者达不到前者记“不大可能”，达到记“有可能”，不记“较有把握”。
- **D5 机制。** 选错 180° 那一支的集，对真值的平均朝向误差远超 0.5 rad，榜上 SP 必然失败；选对了也还要重建位置对真值在 10 cm 内。所以换入的 B2 / B2n 集上界成立需要两件事同时成立，事先估不准。

## 2. 结果

读表记录 `results/t3resub/table_1029.txt`（`stages/evaluate/t3_resub_table.py`）。已交清单里 gb4 那 8 集的导出记录原本只在 mf4090 上，这次拉回 `results/submission/exports/cand_t3_t3pg4_mf4090_*`；ep15、ep12、ep27 新 run 的导出记录从 ml40 拉回 `results/ml40/submission/exports/cand_t3_t3q{hr3s,b2n12,b2r27}_ml40_*`。ep15 新 run 的 4096 世界读数取自 `results/ml40/t3g5/eval_t3qhr3s_ml40.txt`（逐 run 的 eval 记录没有落盘）。

**D1。** 7 个换出的旧 run 导出那一局对自己参考全是 SP、MP 失败（4096 世界 SP-SR 0–0.12）。换入的新 run 4096 世界 SP-SR 0.84–0.99；导出那一局 SP 成功 6 集（ep10、12、14、15、23、27），ep5 失败（MPPE 10.31 cm，略超门槛）；MP 成功 4 集（ep12、15、23、27）。

**D2。** 可比的整版提交只有 1 次：t3m1022aa（第 0 帧对齐）导出那一局对自己参考 SP 成功 10 集、MP 成功 8 集，榜上 SP-SR 10 集、MP-SR 3 集。gb1018e22 没有对齐、世界坐标系不同，按判据不作校准，也没有为它数逐集的对自己参考结果。可比的提交少于 2 次，传递记**未校准**：SP 上 10 对 10 只说明合计相等，不说明是同一批集；MP 只传过去 3 / 8。

**D3。** (a) 成立：Tier 2 AUC 交了更差的 b1019a（0.51091）后，榜上仍显示 0.51379（`results/board/lb_1029_0932.txt`）。所以分数变差的重交不降低榜上分数。(b) 榜上显示的提交时间会跟着最新一次提交走，哪怕分数更差：上面这个 Tier 2 AUC 显示的时间是 10/20 23:06（b1019a），不是 0.51379 那次的 10/14。但 Kaggle 列表里同分队的先后看起来没跟着显示时间变：Tier 3 MP-SR 0 分那一档里，FF 10/28 22:20 重交后显示时间晚于 Team OPS，列表仍排在 Team OPS 前面（`lb_1028_1901.txt` 对 `lb_1029_0932.txt`）。只有这一例，**未核实**。我们自己的看榜脚本按显示时间排同分，重交后脚本算出的名次可能比 Kaggle 实际的差。

**D4。**
- SP-SR：区间 10–16 集，要 ≥ 13 才前进一名（12 集同分时新提交晚于 nima arki 与 Izus_systems）。下界 < 13 ≤ 上界，记**有可能**。前进需要 6 个新增成功里至少 3 集对真值也成功。
- MP-SR：区间 3–7 集，≥ 4 集就单独第一。记**有可能**；按 t3m1022aa 的 3 / 8 粗看，4 个新增 MP 成功里约 1–2 集传过去，未校准。
- AUC：超过 nima arki 要 30 集合计 +3.12。换入的 7 集对自己参考合计只 +2.4（4096 世界）到 +2.5（导出那一局），而对自己参考的 AUC 本来就高于榜上（t3m1022aa 榜上 0.226）。即使全部传过去也不够，记**不大可能**。
- MPPE：超过 nima arki（42.30 cm）要 30 集合计 −229 cm，超过 Izus_systems（38.60 cm）要 −341 cm。换入的 7 集对自己参考导出 MPPE 合计 −416 cm（ep23 一集 −129、ep27 −83、ep10 −73）。榜上误差还含重建对真值的误差，跟踪变好只部分传过去；对称选支选错时点误差反而大。记**有可能**（多半只够前进到第 4）。

**D5。** ep12、ep27 选错那一支则 SP、MP 在榜上必然失败；ep15 的“摊开”那一支同理。ep10、14、23 是 gb5 参考，没有选支，对真值能不能成功取决于 gb5 重建本身。

**结论。** 重交的下行风险小：换出的 7 集原本对自己参考全失败，Kaggle 只保留最好成绩，分数不会因重交变差。上行在 SP-SR、MP-SR、MPPE 三个榜上都“有可能”，AUC 不大可能；三个都没有校准，估不出把握。按 10/19 的第 1 节（领先余量）不满足；按 10/29 新开的“名次和明显变好”一档，也只能说有机会、不能说有把握。真要交，可以用 `--only` 只交 SP-SR、MP-SR、MPPE 三个榜，不碰 AUC。上传前还有两件事：新参考（gb5、hr3s、b2n12h、hr2b2）的第 0 帧对齐参考要齐；含 B2 / B2n 集的清单要不要先问组委会，待定。交不交由 rxzhou 定。
