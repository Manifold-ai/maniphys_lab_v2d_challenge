1. 评测从第 0 帧起跑，不终止，跑到参考结尾。训练课程在最后两段（第 288749568 步起、第 306249728 步起，即 82.5%、87.5%）把 `immediate_first_frame_probability` 设成 0.25、0.50：这部分重置从第 0 帧起跑，没有 50 步冻结、没有肩部与手指偏移，VOC 取课程值 0；其余重置是随机帧加 50 步冻结（`configs/curriculum/recon_body_flash_sac.yaml`；`lifecycle/reset.py` 的 `sample_recon_body_reset`；我们的 run 的展开配置 `runs/cfgcheck/t2-ep25-w2048-cap4m-r3a-ot3-mf4090.recipe.yaml` 第 416、432 行，W&B 汇总 `curriculum/immediate_first_frame_probability` 0.5）。

   ep25 MPPE 103.43 cm、ADD-AUC 0.118；ep4 121.48 cm、0.110。两条 run 目录里都有完整训练状态 `state_349999104.safetensors`（actor、critic、优化器、奖励归一化）。现在交的 Tier 2 清单里 ep25 是 117.09 cm（`t2-ep25-w2048-cap4m-mf4090`），ep4 是 ml40 的 `t2-ep4-w2048-cap10m-r3a-ml40`。“物体不动”的底线 ep25 49.51、ep4 111.51 cm（`results/t2diag/t2_static_floor.txt`）。
4. FlashSAC 支持续训（`training/flash_sac/runner.py` 的 resume 分支，v040_p185_nfg 与 fc_8c778f9 这一段逐行相同）：`training.resume=true`、`training.checkpoint_path=<state>`；读回步数后按新的 `total_environment_steps` 继续，课程按绝对步数取段（超过最后一个门槛就停在最后一段）；replay 没有存（`save_replay: false`），续训从空 replay 开始，`warmup_action: policy`，所以填到 `minimum_size` 409600 之前也用策略动作，不是随机动作；`validate_resume_reference_config` 要求参考配置与存档一致。
5. 学习率是余弦调度，长度默认取 `total_environment_steps` 折算的更新次数（`training/flash_sac/update.py` 的 `learning_rate`，`config.py` 的 `learning_rate_schedule_updates`）。总步数从 349999104 加到 419999744，调度会被拉长，续训起点的学习率从 1.5e-4 回升到约 1.6e-4。把 `training.optimization.learning_rate_schedule_updates` 钉在原长度 683592（349999104 / 2048 × 4）就不会回升。
6. mf4090、buffer 400 万一集 3.5 亿步约 2.3 小时（t2mtr 实测），7000 万步约 30 分钟，加起容器、编译约 5 分钟。

## 1. 做什么

从第 3 条的两个起点各续训 70000640 步（总步数 419999744，能被 2048 整除），每个起点两个分支，共 4 条 run：

- **F（贴近评测）**：最后一段的 `immediate_first_frame_probability` 改成 1.0，所有重置都从第 0 帧起跑、不冻结。终止照起点（ot3，物体 0.3 m）。
- **K（对照）**：课程不改（最后一段 0.5），只多训同样的步数。F 与 K 之差才归到“起跑方式”，F 与起点之差里有一部分只是“多训了”。

两个分支都加：`training.resume=true`、`training.checkpoint_path=/repo/runs/flash_chord/<起点>/state_349999104.safetensors`、`training.optimization.learning_rate_schedule_updates=683592`，其余覆盖与起点的队列行逐项相同（`stages/policy/queues/mf4090_t2mtr.txt`）。F 的课程覆盖在 `curriculum.stages.8` 与 `training.curriculum.stages.8` 各写一处（展开配置里课程出现两次）。run 名 `t2-ep{25,4}-w2048-cap4m-r3a-ot3-ft{f,k}-mf4090`，顺序 ep25 F、ep25 K、ep4 F、ep4 K。

1. 新写 `stages/policy/ft_chain.sh <队列>`（mf4090 上 tmux 里跑，日志 `runs/logs/t2ft_mf4090.log`）：现有训练链的预检要求正式步数为 349999104、冒烟从 0 步起训，续训都不满足，所以单写一条短链，逐条调现成的 `fc_config_check.sh`、`fc_run_watched.sh`（带发散看守）、`fc_eval.sh <run> 419999744`（4096 世界），挂载与训练副本照 `arm_var_chain.sh` 的 `t2m*`（训练 v040_p185_nfg，评测 fc_8c778f9）。队列 `stages/policy/queues/mf4090_t2ft.txt` 手写 4 行加 1 行冒烟，头部注明计划。
2. **起链前核**（不过就不起）：
   - 两份 state 的 sha256 记下，续训期间不动起点目录；
   - 5 份展开配置用 `assert_cfg.py` 断言：resume、checkpoint_path、schedule_updates、终止 0.3（两处）、变体 A 各项；F 的两处课程第 8 段为 1.0，K 的为 0.5；
   - **冒烟**：ep25 F 续训 4096000 步（总步数 354095104），日志里读回的起始步数是 349999104、课程第 8 段、`immediate_first_frame_probability` 为 1.0，结束后 policy 有限。冒烟不过就停，回来改计划。
3. 训练、评测串行跑完约 2.5 小时，起链后预计 17:30 MDT 前后结束。读数写进执行记录。

## 2. 判据（登记）

- **M（覆盖生效）**：每条 run 的 W&B 汇总或日志里起始步数 349999104，F 的 `curriculum/immediate_first_frame_probability` 为 1.0、K 为 0.5，学习率不高于 1.5e-4 加 1e-6。M 不过的 run 不判下面各条。
- 只比最终 checkpoint（第 419999744 步），4096 世界、对自己参考。门槛沿用 t2mtr：同一 run 内 checkpoint 之间就差 23 cm（ep25），所以降 ≥ 23 cm 记“成立”，10–23 cm 只记信号。
- **F1（续训微调有用）**：F 的 MPPE 比起点低 ≥ 23 cm，且 ADD-AUC 不低于起点 − 0.01。ep25：≤ 80.43 cm、≥ 0.108；ep4：≤ 98.48 cm、≥ 0.100。
- **F2（归到起跑方式）**：F1 成立，且 F 比同集 K 低 ≥ 10 cm、ADD-AUC 不低于 K − 0.01。F1 成立而 F2 不成立，记“多训有用，起跑方式没分出来”。
- **F3（有害）**：F 比起点高 ≥ 10 cm，或 ADD-AUC 低 ≥ 0.02，记“只从第 0 帧起跑有害”（多半是忘了后段的参考），不往下推。
- 两集都按上面判，单个种子；成立也只记“有信号”，要换进清单先在同一集上重复一次。成立的那集再与现在交的清单比（ep25 117.09 cm），换不换照策略第 1 节两张榜一起算。
- SP-SR、MP-SR、骨盆失败比例只报。`-ot3-` run 的 chord_sr 与失败原因比例按 0.3 m 算，与变体 A 不可比（t2term 第 3 节）。
- 导出那一局不在这一轮做；不按榜上分数挑东西。这一轮不提交。

## 3. 风险

- 续训从空 replay 开始，前 409600 步只收集不更新，之后 critic 先用新分布的数据；`load_optimizer`、`load_reward_normalizer` 都是 true，奖励归一化的折扣回报清零（`restore_learner_checkpoint`），可能有一小段不稳。发散看守照常。
- F 全部从第 0 帧起跑，回合一终止就回到第 0 帧，参考后段（ep25 第 300 帧以后）只有活得够久的回合才见得到，可能把后段忘掉，F3 管这种情况。
- 起点是 mf4090 的 ot3 run，不是现在交的那条；F 好过起点，不等于好过清单里的那条。
- 只有一个种子。
- mf4090 被占约 2.5 小时。
