## B. ep20 逐帧诊断（mf4090）

### B1 事先登记（与 A1 一起写进实验记录）

- 对象：ml40 满配 ep20 最终 policy（`959c729e…`）为主；mf4090 100 万 buffer 版本（`6545b652…`）作对照，只报数字。
- 做法：官方评测路径原样跑（`evaluate_checkpoint`：确定性、第 0 帧起、`reset_mode` explicit），**256 个世界**，只额外把 rollout 的逐帧数据存成 npz。
- 有效性：诊断这次的汇总指标必须与 ml40 上 4096 世界的评测一致，|ΔADD-AUC| < 0.01 且 |Δchord_sr| < 0.05；不一致就停，不做解读
  （4090 与 L40S 数值不同、世界数不同，这一步确认诊断看到的是被评测的那个行为）。
- **Q1 朝向误差在哪一段累积**：逐帧物体朝向误差（世界中位数与四分位）；第 0、100、209、269、300、360、420、552 帧的值；
  三段（0–208、209–420、421–552）的平均；首次超过 30° 与 86° 的帧。
- **Q2 机器人有没有尝试转电饭煲**：物体实际朝向绕竖直轴的转角（逐帧展开）在 209–420 段的净变化，与参考同段净变化之比；
  以及实际累计转角（逐帧增量之和）。解读规则（事先定）：净变化同向且 ≥ 参考的 50% → 跟着转了；
  累计转角 ≥ 30° 但净变化 < 参考的 50% → 尝试了但没跟上；累计转角 < 10° → 基本没转；其余 → 如实描述。
- **Q3 手有没有沿参考路径走**：209–420 段 palm 位置误差（中位）与物体朝向误差并列。解读：palm 误差 < 5 cm 而物体误差大 →
  手沿参考走了但没带动物体（接触或抓握问题）；palm 误差 ≥ 5 cm → 手本身没跟上。
- **Q4 成功与失败的世界**：按任务原生判据分组（成功 = 全程三组门槛都没越线），分别报 Q1–Q3；失败世界首次越线的帧与原因。

### B2 实现

- `stages/evaluate/diag_rollout.py`（容器内）：包一层 `harness.record_object_pose_rollout`，把 rollout 存成 npz，
  再照 `evaluate_policy.py` 的写法调用 `evaluate_checkpoint`、写出评测 JSON；npz 没生成就报错（防止包装失效却看似成功）。
- `stages/evaluate/diag_rotation.py`（只用 numpy）：读 npz，算 Q1–Q4 与有效性检查，写文本报告，另出一张 SVG
  （逐帧参考 / 实际转角、朝向误差，标出 209–420 段与 86° 门槛）。纯文本生成，不依赖 matplotlib。
- policy 从 ml40 经 Mac 中转到 mf4090，三端核对 sha256；结果经 `record` 落 `results/day1/diag_ep20_*.txt` 与 `.svg`。
- 在 mf4090 上用 setsid 后台跑，日志 `runs/logs/diag_ep20.log`，最后一行 `DIAG_DONE` 或 `DIAG_FAILED`。预计 15 分钟以内。

## 风险与应对

- ml40 共用，占 2 小时以上：开跑前由用户与 yqchen 确认时段（用户已同意执行）；训练中途被别人占卡 → fc_run 按显存不足停下、不自动重试。
- 包装上游内部函数：上游若改了调用方式，包装不生效 → npz 检查兜住。
- 诊断与评测不在同一张卡上 → 有效性检查兜住。
- 训练中断 → fc_run 从最新 checkpoint 续训（Day 1 实测过）。
- 不做：改训练配置、调参、看到结果后改判据或挑 run。
