## A. 满配 snack_box 对照（ml40）

### A1 执行链（`stages/policy/queues/ml40_day1b.sh`，tmux，任何一步不符即停）

1. 把镜像指纹缓存挪开，让下一次训练重新计算 base11 与依赖 freeze。
2. 冒烟 `smoke-snackbox-w2048-cap10m-ml40`：409.6 万步，W&B 记到 `v2d-selftest`，`V2D_MAX_RETRY=0`，`V2D_GPU_APPS=1`。
   冒烟判据（沿用 Day 1）：退出码 0；日志有 `compiled FlashSAC JAX executables`；进度过 409,600；无 `RESOURCE_EXHAUSTED` / `exceeds the base limit`；
   最终 checkpoint 4,096,000 完整（`ckpt_latest.py`）；W&B 同步成功；重新计算的 `image_base11_sha`、`deps_freeze_sha` 等于 Day 1 的
   `e2934912858820b8`、`df0cf35711a68fb3`。迁移后训练路径第一次在新存储上跑，这一步兜住路径权限一类问题。
3. 正式 `ctrl-snackbox-w2048-cap10m-ml40`：官方配方、只给 parquet、默认 1000 万 buffer、无覆盖；`V2D_MAX_RETRY=0`（续训不恢复 replay，
   续出来的就不再是“满配不加覆盖”）、`V2D_GPU_APPS=1`。中途失败就停下，从 0 重来；若人工续训，该 run 标为偏离，不通过也不算“配方/环境有问题”的证据。
4. 4096 世界评测（`fc_eval.sh`，经 `record`）与输入清单。

### A2 事先登记的判据（写进实验记录，开跑前提交）

- 通过：`chord_sr > 0` 且 `maniptrans_sr > 0` 且 ADD-AUC > 不动基线。结构与 ep20、snack 100 万相同，不放松。
- 不动基线的定义：**用评测器自己的顶点**（rollout 的 `object_vertices_o`）算的“物体保持第 0 帧参考位姿”的 ADD-AUC。0.5662 是用 trimesh 顶点、
  从 100 万 run 中间 checkpoint 的配置算的；判定前用 B 里 snack rollout 的顶点复算，差超过 0.002 就用复算值。
- 边缘：`chord_sr` 或 `maniptrans_sr` 的“> 0”只靠 ≤ 3 个世界，或 ADD-AUC 落在门槛 ±0.01 以内 → 标“边缘”，不走 SOP 的任何因果分支，
  下一步按诊断证据定，或补一个种子。
- 混合结果（例如 ADD-AUC 过而 chord_sr = 0）：按判据就是不通过，报告里写清哪一项没过。
- 次要指标（只描述）：逐段 ADD-AUC 与逐段不动基线（用 B 的诊断工具算）；与 100 万版本之差；成功世界计数。
- 通过时的结论只写到：“这个种子在官方样例上胜过不动；ep20 的失败特定于 ep20，原因在我们的管线、这条序列的任务或其他两条序列的差异之中”，
  不写“ep20 数据有错”。不通过时只写到：“这个种子在官方样例上没胜过不动”，原因可能在配方本身、在以静止段为主的门槛，或在环境，
  不写“我们的环境坏了”。

## B. 逐帧诊断（mf4090）

### B1 对象与步骤（`stages/evaluate/diag_day1b.sh`，setsid 后台）

- 三个 policy：ep20 满配（ml40 训，`959c729e…`，主分析）、ep20 100 万（`6545b652…`）、snack 100 万（`072eab94…`，比较静止段失分、复算 snack 门槛）。
- 每个 policy 在同一张 4090 上跑两次，都用 **4096 世界**（装不下就 1024，并在报告里写明）：
  1. 原样的 `fc_eval.sh`（不改动的官方评测）；
  2. `diag_rollout.py`：runpy 运行未改动的 `scripts/evaluate_policy.py`（参数照抄 `fc_eval.sh`），只在 harness 模块里包一层两个函数，存下 rollout。
- 有效性闸 1（同卡，只变“有没有包装”）：两份评测 JSON 的指标逐位相同；不同则说明同卡跨次就不确定，改用 |z| < 3（二项标准误）并在报告里写明。
- 有效性闸 2（描述性）：4090 原样评测与 ml40 上 4096 世界评测之差与 z 值，只用来刻画跨卡差异，不作闸。
- 其余闸（不过即停、不做解读）：包装的两个函数各恰好调用 1 次；T、W、B 与 JSON 一致（B = 1），数值全部有限；
  重算的全程 ADD-AUC 等于 JSON；按位姿算的物体朝向误差与评测器自己的 `object_orientation_rad` 最大差 < 0.1°（查 xyzw 顺序与帧对齐）；
  **已知答案**：由 npz 里的参考算出的“增量 > 0.5° 的首末帧”与“首次超过 1.5 rad 的帧”等于 `static_baseline_*.txt`（ep20：209 / 420 / 269；snack：446 / 704 / 504）；
  **事先预测（ep20）**：任务原生判据下成功的每个世界，第 359 帧物体离自身初始朝向 ≥ 94°。
- npz 另存：`object_vertices_o`、评测器 `object_add` 算的逐帧逐世界 ADD、参考手（palm 坐标帧）位置、上游三个文件的 md5；输出存 float32。

### B2 事先登记的诊断问题

- **Q0 ADD-AUC 在哪一段丢的**（ep20 分 0–208 / 209–420 / 421–552；snack 分 0–445 / 446–704 / 705–799）：逐段 ADD-AUC 与逐段不动基线（同一组顶点、
  参考第 0 帧位姿保持到底）；逐段对全程 ADD-AUC 的贡献（全程 = 各段按帧数加权的平均，线性可加）；逐段物体位置误差。
- **Q1 朝向误差怎么随时间变化**：逐帧物体朝向误差（世界中位与四分位）；关键帧的值；逐世界首次越过 1.5 rad 的帧的分布（另报中位曲线首次越线，注明口径）。
- **Q2 物体有没有被转动**：绕参考主轴的带符号转动进度 φ（逐帧世界系增量投影后累加；零均值抖动相消、不受四元数正负号影响、主轴不必竖直）。
  逐世界报：第 209–420 帧净转动与参考之比（连续值）、第 209 帧到末帧的净转动、段内带符号峰值进度 max_t s·(φ(t)−φ(209))。
  分类（事先定，名字不暗示“跟上了”）：净转动 ≥ 参考的 50% →“净转过半”；峰值 ≥ 30° 且净转动 < 50% →“转过但没保持或没跟上”；
  峰值 < 10° →“基本没转”；其余如实描述。另报净转动比达到“第 420 帧不越门槛”所需比值（1 − 1.5 rad / 参考净转，约 72%）的世界比例。
  单帧增量 > 30° 记为跳变并计数。参考的几何净转约 309°（增量绝对值之和 338° 含抖动）。
- **Q3 手的情况（只报数字，不分类）**：palm 位置误差（两手取大，同评测器）逐段中位；**参考手本身离参考物体表面多远**
  （palm 坐标帧到物体网格顶点的最近距离，逐段；ep20 与 snack 对照）。参考手不贴物体时，手跟得再准也转不动，那属于数据问题。
- **Q4 失败的世界**：只报首次越线的时间与原因分布（按越线分组比较同一批误差是分组定义自带的，不解读）。另报去重后的不同轨迹数（有效样本量）。

### B3 事先写好的“结果 → 下一步”

- 静止段失分为主 → 查接近与抓取阶段、reset 与 VOC 设置；ep20 与 snack 都这样 → 归到配方层（门槛以静止段为主）。
- 净转过半但滞后 → 做 ADR-00001 待办的回放速度对照（1.67 倍速 vs 真实时长）。
- palm 误差大（手没跟上参考）→ 查策略。
- 参考手本身离物体远 → 查重定向管线（接触阈值、手部 IK）。

## 不下的结论（登记）

- 单种子：只说“这个种子在这条样例上胜过或没胜过不动”，不说“配方能/不能训出 snack_box”。
- 1000 万与 100 万之差不归因于 buffer：同时换了 GPU 与机器（Day 1 记录补上这层限定）。
- 误差集中在 209–420 是任何滞后策略（包括完全不动）的默认形状，单凭这点不说旋转是主因，要看 Q0 的逐段对比。
- 诊断数字（4090、非登记世界数的部分）不进判据表，不外推到 Tier 2/3、其他序列或排行榜，也不回头改 Day 1 的判定。
