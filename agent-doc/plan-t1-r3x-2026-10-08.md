# 计划：Tier 1 变体 A 补跑 ep0、ep15、ep5（2026-10-08，第 1 版）

用户 10/8：“按你的建议跑 3 条，两个种子”。建议与依据见 10/8 的判断记录（`results/decisions/jev_claims_t1_variant_8eps_1008.txt`，jev 12 条全部核实，3 道对照题正常）。
第 3 步配方试验登记的是“Tier 1 不通过（S4），不铺开”（`agent-doc/plan-step3-recipe-trial-2026-10-04.md` 第 4、5 节）。这次在 3 条 episode 上补跑变体 A，
是经用户同意的**偏离登记**，只服务于 Tier 1 逐条选，不作为变体 A 有效的证据。时间一律 UTC-6。

## 1. 事实

- **为什么是这 3 条。** 上午提的 8 条（ep0、5、10、13、14、15、17、21）是按 1 世界导出那一次的 MPPE（3.46–5.89 cm）挑的。按 4096 世界评测
  （`results/ml40/day2/eval_t1-ep*-w2048-cap10m-ml40_s349999104.txt`、`results/day2/eval_t1-ep*-w2048-cap4m-mf4090_s349999104.txt`），
  只有 3 条接近第 3 步 Tier 1 试验那 5 条（基线位置误差 3.3–5.6 cm）：

  | ep | 现在交的 run | 4096 世界 MP-SR | 平均位置误差 | 朝向误差 | 失败:骨盆 |
  |---|---|---|---|---|---|
  | 0 | t1-ep0-w2048-cap10m-ml40 | 0.438 | 4.7 cm | 22.6° | 0.105 |
  | 15 | t1-ep15-w2048-cap10m-ml40 | 0 | 4.5 cm | 30.4° | 0.013 |
  | 5 | t1-ep5-w2048-cap10m-ml40 | 0.001 | 6.1 cm | 15.5° | 0.127 |

  其余 5 条平均位置误差 8.9–15.2 cm，4096 个世界里没有一个达标，失败:骨盆 0.076–0.576；变体 A 在试验里让摔的比例从 0.064 升到 0.125。这 5 条不跑。
- **现在的 CSV。** 10/8 逐条选打出的 `runs/submission/csv/track2_tier1_select_1008.csv`（ml40，没有提交）：AUC 0.4198、SP-SR 0.5667、MP-SR 0.4000（12 / 30）、
  MPPE 24.84 cm。ep0、ep5、ep15 选的都是上表里的基线，1 世界的 MP-SR 都是 0（`results/ml40/select_t1/select_1008.txt`）。
- **选择规则不会让 MP-SR 变低**（`stages/evaluate/select_t1.py` 的 `sort_key`、`choose`）：先比 MP-SR，再比 SP-SR，再比 AUC / 0.3780 − MPPE / 25.1706，
  平手保留现在交的那条。
- **输入。** 3 条的 Tier 1 参考 parquet 在 mf4090 上都有，sha256 前 16 位与 ml40 上的相同（`results/ops/r3x_inputs_1008.txt`）。
  mf4090 上训练副本 `v040_p185_nfg` 与评测副本 `fc_8c778f9` 都在；这 3 条在 mf4090 上还没有任何 run。
- **机器。** 10/8 13:55 mf4090 的 GPU 上没有进程、没有长链标记，根分区可用 7876 MB（`results/ops/mf4090_state_1008_1355.txt`）。
  同组的容器 `maniphys-visual-dev-worker-120` 在运行，有 GPU 权限但没有占用（与 10/5 相同）。ml40 空闲。
- **buffer 不同。** 这 3 条的基线是 ml40 上 1000 万 buffer 训的；mf4090 只放得下 400 万，与第 3 步 Tier 1 试验相同。新 run 相对基线同时换了 buffer、机器和配方，
  换上去以后分不清是哪一项起的作用。
- **代价。** 第 3 步 A 段在 mf4090 上 6 条正式训练每条 1:58–2:15，连冒烟与评测共 13.6 小时（10/5 13:30 起链，10/6 03:08 中途检查）。一条 run 留 1 份 state，
  约 0.33 GB；6 条约 2 GB。导出每条约 1 分钟。

## 2. run

6 条，先 seed 42 再 seed 43，链被截断时每条 episode 先有一个变体：

| 顺序 | run | episode | seed |
|---|---|---|---|
| 1 | t1-ep0-w2048-cap4m-r3a-mf4090 | 0 | 42 |
| 2 | t1-ep15-w2048-cap4m-r3a-mf4090 | 15 | 42 |
| 3 | t1-ep5-w2048-cap4m-r3a-mf4090 | 5 | 42 |
| 4 | t1-ep0-w2048-cap4m-r3a-s43-mf4090 | 0 | 43 |
| 5 | t1-ep15-w2048-cap4m-r3a-s43-mf4090 | 15 | 43 |
| 6 | t1-ep5-w2048-cap4m-r3a-s43-mf4090 | 5 | 43 |

训练挂带非有限防护的副本 `v040_p185_nfg`；评测与导出用 `fc_8c778f9`。W&B 标签 `r3x`，不上传 checkpoint（`V2D_WANDB_UPLOAD_CKPT=0`）。

## 3. 做法

1. **代码**（各带测试）：
   - `stages/policy/make_r3x_queue.py`：从 ml40 基线的期望表与队列行派生上面 6 条（复用 `make_trial_queue.py` 的 `baseline()` 核对），写
     `stages/policy/queues/mf4090_r3x{.expect.tsv,_smoke.txt,.txt}` 与导出清单 `stages/evaluate/exports/cand_t1_r3x_mf4090.tsv`；测试 `test_make_r3x_queue.py`。
   - `stages/policy/arm_r3x_chain.sh`：起链前核对（GPU 是 4090、来历干净、日志与会话不存在、GPU 空、可用 ≥ 4000 MB、副本按清单核对、run 目录不存在、
     导出清单与期望表一致、12 份配置 precheck 与配方断言），再起三个会话：训练链 → 评测链（等训练链结束，只评最终 checkpoint，4096 世界）
     → 导出链（等评测链结束，1 个世界，`V2D_FALLBACK_MAX=0`）。`V2D_ARM_DRYRUN=1` 只核不起。
   - `stages/evaluate/select_t1.sh`：输出名与输入目录改由 `V2D_SELECT_TAG`、`V2D_SELECT_DIR` 指定（不设时是 10/8 的行为）；同一标签的分数文件已存在就拒绝。
   - `stages/evaluate/select_t1_compare.py`：把这一次选择与 10/8 逐项对比（第 4 节 C1–C5）；测试 `test_select_t1_compare.py`。
   - `stages/evaluate/relay_t1x.sh`：早上把 mf4090 上导出 ok 的候选经 Mac 管道转到 ml40，并在 ml40 上拼出这一次的输入目录 `runs/select_t1_r3x/`
     （10/8 的 48 个候选硬链接进来，加新候选）。Mac 只转发。
2. **部署**：提交、推送；两台都空闲，各同步一次（ml40 要拿到改过的 `select_t1.sh`，同步要赶在 Tier 2 之类的长链起之前）。测试在 mf4090 上跑，经 `scripts/dev/record` 落盘。
3. **起链**（mf4090）：`fc_config_check.sh` 展开 12 份配置 → `V2D_ARM_DRYRUN=1 arm_r3x_chain.sh` → `arm_r3x_chain.sh`，都经 record 落盘到 `results/r3x/`。
4. **等**：链在服务器上跑，Mac 可以离线。预计 10/9 早上 6–7 点前后导出链结束。
5. **集中与选择**（10/9，Mac 在线时）：`relay_t1x.sh` → ml40 上 `V2D_SELECT_TAG=r3x V2D_SELECT_DIR=runs/select_t1_r3x stages/evaluate/select_t1.sh <已同步的 commit URL>`
   → `select_t1_compare.py`（ml40 宿主 python3）→ 拉回结果、写执行记录、过 jev、向用户回报。**不提交**；交不交、什么时候交仍由用户定。

## 4. 判据（执行前登记）

| 编号 | 判据 |
|---|---|
| R1 训练健康 | 每条 run：冒烟通过，有 DONE，最终 policy 有限，没有 `NONFINITE_GUARD_STOP`，看守没有止损 |
| R2 评测 | 每条有 DONE 的 run 有 4096 世界评测：`world_count` 4096、`non_finite_worlds` 为空、`step_count` 与 sha256 和导出相同（导出链的候选条件） |
| R3 导出 | 每条导出状态 `ok`（只用最终 checkpoint，不回退） |
| R4 选择门 | `select_t1.py` 的 A 门（≤ 1e-9）、B 门（≤ 1e-4）都过；`select_t1_compare.py` 的 C1–C5 都过 |

`select_t1_compare.py` 的五项：C1 10/8 的 48 个候选分数不变（≤ 1e-9）；C2 新出现的候选都在导出清单里；C3 其余 27 条 episode 选中的 run 不变；
C4 ep0、ep5、ep15 选中的是原来那条或这条 episode 的新候选，且按登记规则不比原来差；C5 打包合计等于 30 条选中者的平均（≤ 1e-6）。

- R1–R3 不过的 run 不进候选，照实记下，不换参数重跑。原因在基础设施（W&B 网络、GPU 被占、磁盘）时，可以用同一配置原样重跑一次，记下。
- R4 任一项不过：不用这一次的 CSV，停下查原因。
- 选择规则沿用 10/8 登记的那一套，不改；每个 checkpoint 只导出一次，不为“抽”更好的一次重导。
- **只报**：ep0、ep5、ep15 各候选的四项分数与 4096 世界 MP-SR、换没换；新 CSV 与 10/8 CSV 的合计对比；6 条 run 的 4096 世界指标与对应基线并列，
  注明 buffer、机器、配方同时变了，不作为变体 A 的证据。

## 5. 风险

- **摔倒**：变体 A 已知会让摔的比例升高。逐条选只在交上去的那条轨迹更好时才换，摔了的那次不会进 CSV。
- **抽签**：候选越多，交上去的分数越多地反映挑选。报告里把选中者的 4096 世界 MP-SR 并列，区分实力与运气。
- **GPU 被占**：同组容器若开始用 GPU，训练链在下一条 run 前停下。停了就报告并问用户，不动别人的容器。
- **磁盘**：6 条约 2 GB，起链时可用 ≥ 4000 MB；训练链在不到 1200 MB 时停。
- **Mac 离线**：链在 mf4090 的 tmux 里跑，不受影响；第 5 步要等 Mac 在线。
- **ml40 同步**：`select_t1.sh` 的改动要在 ml40 起别的长链之前同步过去，否则同步会被长链标记拦下。
- **档位隔离**：只碰 Tier 1。
