3. **能拿到机器人手掌位置**：ReconBody 终止对象（`env.termination`，`ReconBodyTermination`）带 `bodies_per_world`、`wrist_frames`

   `transform_point(body_q[w × bodies_per_world + body_ids[h]], body_to_frame_pos[h])`。诊断时在每一步之后用同样的公式把两只手掌与物体的位置抄出来即可，
   不改评测器，只多读不写。
4. **成功判据**（`evaluation/metrics.py:296–347`）：逐世界先对帧取平均。MP-SR：位置 < 0.03 m 且朝向 < 30°；SP-SR：位置 ≤ 0.1 m 且朝向 ≤ 0.5 rad。

## 3. 方法

### 3.1 诊断 rollout（GPU，`diag_rollout.py --palms`）

- 与已有的评测同一运行时（默认挂的上游 v0.4.0，不设 `V2D_FC_SRC`）、同一 checkpoint（`policy_349999104`）、4096 个世界。
- `--palms`（新）：把传给 `record_object_pose_rollout` 的 `jax_env` 包一层，每次 `step` 之后用一个只读 kernel（`stages/evaluate/diag_palms.py`）
  按事实 3 的公式抄下两只手掌的世界坐标，同时抄下物体刚体的位置。不加 `--palms` 时脚本行为不变。
- **同步闸**：抄下的物体位置必须与评测器自己记的 `achieved_pose_w` 逐位相同（最大差 < 1e-6 m）。不同说明抄的时机与评测器不是同一步，手掌数据作废。
- **手掌坐标帧闸**（第 2 版）：评测器每一步记了“两只手掌到参考手掌距离的较大者”（`tracking_error` 的 `palm_position_m`）。由抄下的手掌与 npz 里的参考手掌重算，
  最大差要 < 1e-4 m，证明抄的是评测器打分用的那两个坐标帧、左右没对调、帧没错位。评测器每一步先按当前帧号打分、再推进帧号，所以第 t 步对参考第 t 帧，
  与物体打分的对齐方式相同；另报错一帧时的差（只报）。试跑（16 个世界）与正式分析都查这两道闸。

### 3.2 分析（CPU，`stages/evaluate/diag_phase.py`，只用 numpy）

**闸**（任何一道不过：只打印数字、不分类，退出码 3）：
- V0 形状：帧数、世界数与评测 JSON 一致，物体刚体 1 个，手掌数据存在且同步闸通过；
- V1 同卡：这次评测的指标与本机已有的 `eval_349999104_w4096.json`（本机评测链算的，有本机日志）逐位相同，或 chord_sr |z| < 3 且 |ΔADD-AUC| < 0.005（同 Day 1b 的 G1）；
- V2 重算：由 npz 的逐帧位姿按事实 4 重算的 MP-SR、SP-SR 与这次评测 JSON 的 maniptrans_sr、spider_sr_uncentered 相等（差 < 1e-9）；由 npz 的逐帧 ADD 重算的 ADD-AUC 与 JSON 差 < 1e-6。

**参考的分段**（只用参考，不看 rollout）：
- 主动手：参考接触标记里有接触帧的那几只手；t_c = 主动手里最早的接触帧；
- 物体开动帧 t_m：t_c 之后第一个参考物体相对 t_c 时的位姿移动超过 2 cm 或转过 5° 的帧（没有就记“参考物体在接触段里不动”）；
- 段：接近 [0, t_c)、接触 [t_c, 最后接触帧]、之后。

**逐世界的量**：物体位置、朝向误差（同评测器）；机器人手掌到物体表面的距离 d_rob（评测器的 500 个顶点，按这一帧的实际物体位姿放到世界系）；
参考手掌到参考物体表面的距离 d_ref（同样 500 个顶点）。

**逐世界分类**：MP-SR 成功的世界先归“成功”（它们身上若有下面接近或抓取的标记，记作误报，只用于第 4 节的对照检查）；
失败的世界按下面的顺序先中先停：
1. **接近失败**，取 [t_c, t_c+10) 帧的中位数：
   - A1 物体被提前碰动：t_c 时物体误差已超过 3 cm 或 30°；
   - A2 手没到位：t_c 时在接触的某只手 d_rob − d_ref > 5 cm。
2. **抓取失败**（接近通过；参考物体在接触段里不动时只查 G1）：取开动窗口 [t_m, t_m+30)（30 帧 = 源数据 1 秒）：
   - G1 手没贴住：窗口里“在接触的每只手都满足 d_rob ≤ d_ref + 3 cm”的帧不到一半；
   - G2 物体没跟上：参考物体在窗口里移动 ≥ 5 cm 而实际移动不到参考的一半，或参考转过 ≥ 15° 而实际转过不到一半。
3. **跟踪失败**（K）：接近、抓取都通过，但这个世界 MP-SR 不过。

门限的来由：3 cm、30° 是 MP-SR 自己的门槛；5 cm 是手掌坐标帧的位置余量（palm 误差的终止门槛是 15 cm，Day 1b 的 T3 用一半 7.5 cm，这里更严一点）；
一半、30 帧、2 cm / 5° 是事先定的整数。另报灵敏度：A2 用 2.5、10 cm，G1 用 1.5、6 cm 重分一次（只报）。

**输出**：每条 run 各类的世界数与比例；各段对时间平均位置、朝向误差的贡献；在接触段里“手贴着物体”的帧比例；每类挑中位的 3 个世界号，
供 viser 查看器复看（不导视频）。
第 2 版另加（只报，不改登记的规则）：A2 世界的手何时到位（相对 t_c 的帧数四分位，30 帧内到位、更晚才到、一直没到各多少），用来分清“手没来”与“手来晚了”；
A1 世界在第 0–9 帧与 t_c 前 10 帧的位置误差，用来分清“手碰动了物体”与“物体一开始就偏了”；K 世界里接触段贴合不到一半的比例（开动窗口之后才松手的会落在这里）；
失败世界里只有位置不过、只有朝向不过、两样都不过各多少（交通锥、喷瓶这类对称物体的朝向项要单独看）；G1 窗口里实际数了几帧。

## 6. 风险

- 抄手掌位置的 kernel 每步多一次启动、整段多一次拷回，rollout 会慢一点；同步闸保证抄的是同一步的状态。V1 再证明它没有改变评测结果。
- npz 每条约 300 MB（4096 世界）；mf4090 方盒训完约剩 5 GB，三条加对照约 1.2 GB，诊断完只留 npz、删 hydra 目录。
- “手掌坐标帧到物体表面的距离”不是手指到表面的距离：握住时也有几厘米。所以比的是机器人与参考之差（d_rob − d_ref），不看绝对值。
- 分类规则是启发式的。有正向对照兜底；灵敏度只报，不改结论的门限。
