## 问题与假设

问题：在 3.5 亿步的预算内，把 ep20 参考按真实时长而不是 1.67 倍速播放，转动的落后量会不会变小，变小的部分出在哪一段？

| 假设 | 含义 | 对真实时长一臂的预测 |
|---|---|---|
| 速度上限 | 机器人转不了参考那么快 | 变化主要在快转段（源 314–420 / 真实时长 523–700）；现有数据里满配在快转段只落后约 10°，所以预计变化很小 |
| 起步要时间 | 物体开始转之前机器人需要大致固定的一段时间 | 起转段（源 209–269 / 真实时长 348–448）新增的落后量变小；起步时间若按秒固定，约从 75° 降到 45° |
| 与时间无关 | 例如参考手没贴着物体（T4），放慢也转不起来 | 起转段新增的落后量基本不变 |

## 设计

2 × 2：buffer {1000 万（ml40），100 万（mf4090）} × 回放 {1.67 倍速（Day 1 已有），真实时长（新训）}。每格一个种子（42），
总步数 349,999,104，curriculum 不变。两臂的差别：`task.source_frame_playback=false`，以及为此放宽的两个 palm 校验容差（事实 15）；
另有只影响日志的 `logging.upload_checkpoints=false`。

- 满配这一对回答 T2（触发来自它），判定只看这一对。100 万这一对的 policy 呈双峰（565 个世界基本没转）、失败以手越线为主，
  中位数会被手的变化带着走，所以只作描述，方向相反时注明。
- 总步数相同：curriculum 与算力一致。真实时长的参考长 1.67 倍，每个参考帧被访问约 0.6 倍、帧又密 1.67 倍，净方向不明；
  结论一律说成“在 3.5 亿步预算内”，不说“速度是 / 不是原因”。
- 两臂各按自己的速度评测（事实 5），关注段与阶段按时间对齐（事实 14）。不做交叉评测：官方口径未知，这个数现在没有决策用途。
- 噪声下限：每一臂评最后三个 checkpoint（330,012,672 / 340,013,056 / 349,999,104 步），臂的取值用三者平均，
  三者之间的最大差当作这一臂的波动（设计审查第 3 条）。这只是同一条 run 末段的波动，比不同种子之间的差小；不另开重复种子的 run。

## 判据（事先登记）

**有效性**：两条正式 run 各一段跑完；冒烟、参考核对与诊断试跑全过；全部诊断报告 VALIDITY PASS；
每份报告的 `frames` / `segments` 与所属一臂相符（1.67 倍速 553 帧、209–420；真实时长 921 帧、348–700），两臂参考净转相差 ≤ 1°。
任何一条不满足：只列数字、不判定。

**主指标** L：第 420 帧（真实时长第 700 帧）绕参考主轴、从第 0 帧起算的落后量，世界中位（诊断 Q2b）。每臂取三个 checkpoint 的平均。
S = 各臂三个 checkpoint 之间最大差的最大值；E = max(15°, 2S)。Δ = L(1.67 倍速) − L(真实时长)，只看满配这一对，正数表示真实时长落后更少。

| 判定 | 条件 |
|---|---|
| 真实时长更好 | Δ ≥ E |
| 真实时长更差 | Δ ≤ −E |
| 预算内没有差别 | \|Δ\| < E/2，且真实时长一臂健康、训练已走平 |
| 无结论 | 其余情况 |

- 健康：真实时长满配操作段的 palm 误差中位 ≤ 7.5 cm（T3 的门槛）。
- 走平：真实时长满配第 330,012,672 步的 L 减第 349,999,104 步的 L ≤ max(10°, S_对照)，S_对照 是满配逐帧回放一臂三个 checkpoint 的最大差（登记后改动 2）。
- 机理（只在“真实时长更好”时给）：起转段与快转段新增落后量的变化各占 Δ 的多少。起转段 ≥ 2/3 记“起步要时间”，快转段 ≥ 2/3 记“速度上限”，其余记“混合”。
- 100 万这一对：同样的数全部照报，另报“净转过半”那部分世界的 L 与首个越线原因的计数；它的 Δ 与满配方向相反且 |Δ| ≥ E 时注明。
- 满配这一对缺失（ml40 没跑成）：不给判定，只列数字。

判定由 `stages/evaluate/playback_compare.py` 按上表机械给出；脚本与合成测试在分析链开跑前写好、提交。

## 结果 → 下一步

- 真实时长更好（起步要时间）：物体开始转之前机器人确实需要时间。下一步仍是 T4：起转时参考手到底有没有贴着物体。
- 真实时长更好（速度上限 / 混合）：如实报告；不改上榜训练的回放方式（事实 15），等组委会答复。
- 预算内没有差别：转动落后与回放速度无关，下一步转 T4（参考右手离物体 5.9 cm，查重定向）与 T1（操作开始前预转约 20°）。
- 真实时长更差：说明随回放一起变的预览与视界（事实 8）在起作用，如实报告，不改配置。
- 无结论：如实报告；要不要加重复种子由用户定。

不管结果如何，给组委会的邮件都要问：官方评测按哪种速度播放；评测是否沿用 checkpoint 自带的回放设置（上游 harness 是沿用的）；
事实 15 里 G1 只接受逐帧回放这一点是不是有意的。
