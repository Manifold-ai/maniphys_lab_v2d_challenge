## 0. 事实

1. **SP-SR 是对时间取平均后再比门槛**：每个世界先对全部帧取平均位置误差与平均朝向误差，平均位置 ≤ 0.10 m 且平均朝向 ≤ 0.5 rad 算成功（官方源码摘录 `results/batch1/metric_threshold_facts.txt` 第 296–316 行：`_per_world_pose_error` 先对帧 `.mean(axis=0)`，`spider_success` 再与 0.1 m / 0.5 rad 比；转述见 `agent-doc/plan-diag-mpsr0-2026-10-02.md` 第 4 条）。所以几十帧的朝向翻转不一定让 SP-SR 归零，关键是全程平均。
2. **ep27**（woven_basket，有一个对称元：绕主轴 2 转 180°）：gb5 参考拿着那段第 132–476 帧里，第 181–189 帧一个风暴转 171°（两端按对称取模接得上，桥接），第 194–197 帧一个切换转 100°（接不上）。去跳变撤掉切换后，段尾与放下后歇着位姿按对称取模只差 22.7°，摊到 344 帧每帧 0.07°；上一版工具的上限是 20°（照 `t3_dynamics_post.MAX_OFFSET_DEG` 定的约定值），所以这集没改（`results/ml40/t3hand/held_fix_ml40.txt`）。读法：撤掉切换以后只剩 22.7° 的净转动，要两个风暴在半秒内先翻 171° 再翻 100° 才对得上，被两只手抱着的篮子做不到。保留切换不是更好的解释。
3. **ep27 现有的跟踪**：关掉朝向终止的 run 导出那一局位置全程跟住（最大 8.4 cm），但仿真里的篮子停在翻转前那一支，与参考翻转后差约 126°，4096 世界朝向误差均值 88.6°、SP-SR 0、MPPE 17.1 cm（`results/t3g5/eval_t3pocoff_mf4090.txt`）。gb5 原 run 第 184 帧过 10 cm、第 191 帧丢。
4. **ep15**（牌子，无对称）：拿着那段第 110–626 帧里第 497–502 帧切换 168°；撤掉切换段尾差 119°（上限 20°，没改）。参考里两只手在第 484–526 帧都没有接触标记；第 440–496 帧与第 532 帧以后，物体在右手掌系里的相对朝向各自稳定，两段之间差约 160°（`results/ml40/t3fix2/turn_ep15.txt`），即一次换握：松手、牌子转半圈、再握住。参考改不了；关掉终止的 run 导出那一局全程平均朝向 0.572 rad（第 0–497 帧 0.414、第 503–715 帧 0.905；4096 世界的朝向均值是 33.5° = 0.585 rad），离 SP-SR 的 0.5 rad 很近（`results/ml40/t3hand/o2_ep15.txt`、`results/t3hand/o2_ep15_post.txt`）。`plan-t3oo` 的两条臂正是针对这两段：σ 0.4 收翻转前、σ 1.0 收翻转后。
5. **新参考已经出来，并过了与 ep13 同一套检查**（10/28 11:4x–12:0x MDT，ml40 CPU）：
   - 工具：`t3_held_fix.py` 的上限可以用环境变量 `T3_HELD_FIX_MAX_D` 单次覆盖（默认 20°，允许 (0, 30]，用到的值写进 provenance）；工具在 `track2/t3sil-choose` c956044（跑 `_hr2` 用的版本；记录头里的 source 是主仓 commit，不是工具的），b89841e 把覆盖挪进 `max_d_from_env` 并加测试，8 个测试都过。只对 ep27 跑，`T3_HELD_FIX_MAX_D=25`，出 `tier3_cari4d_gb5_best_dr2s_hr2`：两个风暴一个桥接、一个撤销，空闲段跳变帧 10 → 0，改了 344 帧（`results/ml40/t3fix2/held_fix_hr2.txt`）。

## 3. 风险

- 上限从 20° 放到 25° 是这一集的单次例外，依据是事实 2 的读法和 0.07°/帧的摊开速度；25 是看到 22.7 之后定的，是事后定的尺（ep09 的 23.5° 也会过），所以定为规则：以后任何集要超过 20°，都要先在计划里点名登记，才能用 `T3_HELD_FIX_MAX_D`；若这 22.7° 其实是某一刻的真实转动，摊开后任一帧对真值最多差约 23°，全程平均更小，仍在 SP-SR 的 0.5 rad（28.6°）之内。
