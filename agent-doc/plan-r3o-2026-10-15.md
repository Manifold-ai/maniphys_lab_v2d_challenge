### 2.1 r3o 的改法（只改训练副本，评测器不动）

- 新副本 `v040_p185_nfg_oo` = `v040_p185_nfg` + 一个补丁（`third_party/patches/` 下，注明基于的副本与上游 v0.4.0）。评测与导出照旧用 `fc_8c778f9`。
- 新增第 13 项 `object_orientation`：θ 用终止已有的同一套量算，即 `quat_geodesic_angle(transform_get_rotation(body_q[物体刚体]), command.body_target_quat_w[世界])`，
  物体刚体与 `object_position` 用的是同一个；奖励 exp(−θ²/σ²)，不计对称，与评测器一致。
- **开关走环境变量，不进 Hydra 配置**（第 3 版）：`V2D_OBJ_ORI_WEIGHT`（默认 0）、`V2D_OBJ_ORI_STD`（默认 0.4），由新文件 `v2d_extras.py` 读取与校验。
  checkpoint 存的配置与课程因此保持上游的 12 项，8c778f9 照样能读；第 13 项只在训练副本里：`recon_body.py` 的 `set_weights` 与
  `curriculum.py` 的 `weights_for` 遇到课程没写的第 13 项时补上环境变量的权重（9 段相同）。出处：训练日志开头打印一行
  `V2D object_orientation term: weight=… std=…`，`fc_run.sh` 的运行记录写 `fc_src`、`obj_ori_weight`、`obj_ori_std`，队列行与 run 名（`-r3o-`）也写着。
  `scripts/dev/in-flash-chord` 把这两个变量按名字转进容器。权重 0 时目标函数 kernel 的分数与上游逐位相同（只在 CPU 上测过；GPU 上重编译的
  kernel 没有逐位核对）；学习器重算奖励按 13 项求和，浮点归约顺序可能变，不保证逐位相同。`fc_run.sh` 另有守卫：run 名带 `-r3o-`、设了
  `V2D_OBJ_ORI_WEIGHT`、副本打了物体朝向补丁，三样要么都有、要么都没有（契约 POLICY-I007 至 I010）。
- r3o 的取值：σ = 0.4 rad、权重 1.0，9 段相同；r3a 的两项照旧。取值只看现有的 `palm_orientation`（σ 0.4、权重 1.0）、`object_position`（权重 1.0）
  与公开的 MP-SR 常数 30°：误差 5°、15°、30° 时奖励约 0.95、0.65、0.18。σ 不放宽的理由：r3a 的朝向终止在 0.6 rad，训练里朝向误差超过 34° 的
  世界当步就终止，新项起作用的区间是 0–34°，σ 0.4 在这段从 1.0 降到 0.105，对比够；σ 0.8 只降到 0.57（审查第 9 条，另见第 3 节的“只报”项）。
